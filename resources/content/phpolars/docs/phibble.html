phibble defines a table contract with several backends: its in-memory DataFrame, SqlTable for PDO databases, and Phibble\Polars\PolarsTable, which runs on a Polars DataFrame when the php_polars extension is loaded. phplyr’s verbs work on any of them, so a phplyr pipeline runs in Polars when it starts from a PolarsTable. The backend ships with phibble ^0.2; install phpolars to enable it. phibble’s Backends page compares the backends.

A phplyr pipeline on a PolarsTable runs in Polars:

  • Method chain (PHP 8.3+)
  • Pipe (PHP 8.5)
use Phibble\Polars\PolarsTable;
use function Phplyr\{col, mean, n, phplyr};

$table = PolarsTable::fromPolars(Phpolars\read_csv('sales.csv'));   // or PolarsTable::fromTable($dataFrame)

$out = phplyr($table)
    ->group_by('store')
    ->filter(col('units')->gt(mean('units', na_rm: true)))
    ->summarise(orders: n(), avg_units: mean('units'))
    ->get();
use Phibble\Polars\PolarsTable;
use function Phplyr\{col, filter, group_by, mean, n, summarise};

$table = PolarsTable::fromPolars(Phpolars\read_csv('sales.csv'));   // or PolarsTable::fromTable($dataFrame)

$out = $table
    |> group_by('store')
    |> filter(col('units')->gt(mean('units', na_rm: true)))
    |> summarise(orders: n(), avg_units: mean('units'));

$out is a PolarsTable, and $out->collect() returns a Phibble\DataFrame.

What runs in Polars

Verbs given column names or phibble expressions (Phibble\Expr, which phplyr’s helpers such as col(), mean(), and n() build) run in Polars with dplyr’s semantics: NA propagates, aggregates default to na_rm = FALSE, grouped mutate() and filter() evaluate aggregates and windows per group, groups follow sorted key order, and joins follow dplyr 1.2, including join_by() inequality and rolling joins. Pivots, stringr and lubridate functions, and phibble’s reference fixtures all run natively.

PHP closures cannot run on Polars threads. A verb given a closure converts the table to a phibble DataFrame, runs there, and converts the result back; PolarsTable::$fallbacks counts these conversions. See Performance for their cost.

PolarsTable::fromTable() throws when a list column would not round-trip exactly, for example when named arrays with different keys would become structs.

Missing values

phibble and phplyr treat PHP null as R’s NA, and a pipeline on a PolarsTable keeps those semantics. The phpolars API itself (DataFrame, LazyFrame, Expr, and Series) follows Polars, which treats null differently. Code moved from a phplyr pipeline to direct phpolars calls can return different results on the same data.

Operation phplyr, as in dplyr phpolars, as in Polars
sum, mean, min, max, std NA if any value is NA, unless na_rm: true Nulls are skipped. col('x')->sum() over [1, null, 3] is 4.
Counting n() counts rows count() counts non-null values; len() counts rows
Comparison with null NA null. eqMissing() and neMissing() treat null as a value.
Arithmetic with null NA null
filter A row whose condition is NA is dropped A row whose condition is null is dropped
Sorting NA sorts last null sorts first; pass nullsLast: true
Join keys NA matches NA unless naMatches: false null matches nothing unless nullsEqual: true
NaN is.na() is true for NaN NaN is a float value. isNull() is false for it; use isNan().

To get dplyr’s results from phpolars, compare nullCount() with zero before aggregating, sort with nullsLast: true, and join with nullsEqual: true.

Moving data directly

Without the backend, DataFrame::fromPhibble($table) reads any phibble table through toColumns(), and $df->toPhibble() returns a Phibble\DataFrame, which needs phibble v0.2 or later.
