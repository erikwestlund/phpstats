This example gives each day of sales the price in force on that day and a rolling mean over the last three calendar days.

Prerequisites: the phpolars extension, which needs no Composer packages. Getting started covers installing it.

The input is two small data frames: unit sales for six days in March 2024, with no sales recorded on March 3 and March 7, and a list of two price changes. Save the script as time-series.php and run it with php time-series.php:

<?php
use Phpolars\DataFrame;
use function Phpolars\col;

// Daily unit sales, with no rows for March 3 and March 7.
$sales = (new DataFrame([
    'date' => ['2024-03-01', '2024-03-02', '2024-03-04', '2024-03-05', '2024-03-06', '2024-03-08'],
    'units' => [12, 15, 9, 20, 14, 18],
]))->withColumns(col('date')->str()->toDate());

// List prices, each in force from its date until the next change.
$prices = (new DataFrame([
    'from' => ['2024-03-01', '2024-03-05'],
    'price' => [4.50, 4.95],
]))->withColumns(col('from')->str()->toDate());

$priced = $sales
    ->joinAsof($prices, leftOn: 'date', rightOn: 'from')
    ->withColumns(
        col('units')->mul(col('price'))->alias('revenue'),
        col('units')->rollingMeanBy('date', '3d')->round(2)->alias('units_3d'),
    );

echo $priced;

joinAsof() matches each row of $sales to the last row of $prices whose from date is on or before its date. Sales from March 5 onward get the new price. Both data frames must be sorted by their join columns. The strategy argument can match the next row or the nearest row instead, and tolerance limits how far apart the dates may be.

rollingMeanBy('date', '3d') averages the units over a window of three calendar days ending at each row. The window counts time, so a missing day shortens it: the window for March 4 holds March 2 and March 4, and its mean is 12.0. rollingMean(3) would average the last three rows instead. Durations are strings such as '3d', '2h30m', '1w', and '1mo'.
