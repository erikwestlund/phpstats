phpolars brings Polars to PHP as a native extension written in Rust. It follows the py-polars API: the same classes, methods, and semantics, with camelCase method names and snake_case functions. A test suite compares 314 cases against py-polars 1.43.2, and all of them match.

$sales = read_csv('sales.csv', tryParseDates: true);

$top = $sales
    ->filter(col('units')->gt(0))
    ->withColumns(col('units')->mul(col('price'))->alias('revenue'))
    ->groupBy('product', maintainOrder: true)
    ->agg(col('revenue')->sum()->round(2), ['orders' => len()], col('price')->mean()->round(2)->alias('avg_price'))
    ->sort('revenue', descending: true);

echo $top;

What it includes

  • DataFrame and LazyFrame with py-polars’ verbs: select, withColumns, filter, sort, groupBy/agg, join, unique, pivot, unpivot, explode, describe, and more.
  • Expressions with arithmetic, three-valued logic, aggregations, window functions (over), when/then/otherwise, and the str, dt, list, struct, and name namespaces.
  • Series, with the same expression methods.
  • CSV, Parquet, JSON, NDJSON, and Arrow IPC reading and writing, with lazy scans and streaming sinks.
  • A thread-pool cap for PHP-FPM (php_polars.max_threads).
  • A backend for phibble, Phibble\Polars\PolarsTable, that runs phplyr pipelines in Polars. It ships with phibble ^0.2; see phibble’s Backends page.

The family

phpolars is one of a set of PHP 8.3+ packages for data work. phibble is a pure-PHP data frame and the shared table contract. phplyr adds dplyr verbs on top of it. phit fits regression and mixed models. phpolars is the optional fast backend: install it when the data is large or the pipeline is heavy, and keep using phplyr’s verbs.
