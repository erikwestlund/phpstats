Installation

composer require phpstats/phplyr

Requirements

  • PHP 8.3, 8.4, or 8.5. CI tests all three on Linux. Pipelines written with the pipe operator |> need PHP 8.5, and method chains run on all three.
  • The mbstring extension, which phplyr requires.
  • The PDO extension, which phibble requires.

Composer installs phibble (0.3, 0.4, or 0.5), which provides the tables, and symfony/polyfill-php84, which provides PHP 8.4’s functions on PHP 8.3.

Optional features

Statistical models. lm(), glm(), lmer(), and glmer() call phit’s model functions. Either of two implementations provides them, and phplyr calls both the same way:

  • The phit extension, written in Rust. phplyr works with phit 0.1 and later. CI builds it from phit’s main branch.
  • phit-polyfill, the same functions in PHP, for systems where the extension cannot be installed. CI tests phplyr with phit-polyfill 0.3. Install it with composer require phpstats/phit-polyfill. Models describes what it leaves out.

Native descriptive statistics. With the phit extension loaded, mean(), sd(), var_(), median(), and quantile() call phit’s statistics functions. Without the extension, including with phit-polyfill, they run in PHP and give the same results.

Polars. The phpolars extension provides phibble’s PolarsTable, which runs a pipeline in Polars. See Compatibility and limitations.

Transliteration of names. With the intl extension, make_clean_names() and clean_names() transliterate non-ASCII names the way R’s janitor does. Without it, they use iconv, and some names can differ from janitor’s. See janitor.

Database tables. Phibble\tbl() runs a pipeline as SQL through PDO. It needs the PDO driver for the database: SQLite, PostgreSQL, or MySQL. See Databases and expressions.

A first script

Create a Composer project in an empty directory and download the example data, test scores from 250 students in 12 schools:

composer require phpstats/phplyr
curl -O https://raw.githubusercontent.com/phpstats/phplyr/v0.4.3/docs/data/schools.csv

Save one of the scripts below as first.php and run php first.php. Both print the five schools with the highest average score among students who studied at least five hours.

  • PHP 8.5+
  • PHP 8.3–8.4
<?php

require __DIR__.'/vendor/autoload.php';

use Phibble\DataFrame;
use function Phplyr\{filter, group_by, summarize, arrange, head, desc, n, mean, sd};

$schools = DataFrame::fromCsv('schools.csv');

echo $schools |>
    filter(fn ($r) => $r->study_hours >= 5) |>
    group_by('school') |>
    summarize(students: n(), avg_score: mean('score'), sd_score: sd('score')) |>
    arrange(desc('avg_score')) |>
    head(5);
<?php

require __DIR__.'/vendor/autoload.php';

use Phibble\DataFrame;
use function Phplyr\{phplyr, desc, n, mean, sd};

$schools = DataFrame::fromCsv('schools.csv');

echo phplyr($schools)
    ->filter(fn ($r) => $r->study_hours >= 5)
    ->groupBy('school')
    ->summarize(students: n(), avg_score: mean('score'), sd_score: sd('score'))
    ->arrange(desc('avg_score'))
    ->head(5);

Imports

phplyr’s functions are namespaced functions in Phplyr. Import the ones a file uses with use function:

use Phibble\DataFrame;
use function Phplyr\{phplyr, filter, mutate, group_by, summarize, arrange, desc, n, mean};

A method chain needs phplyr() and the helpers it calls, such as n(), mean(), and desc(). The table functions are the chain’s methods, so they don’t need importing.

Some phplyr functions have the same names as PHP built-in functions. In a file that imports one of them, the bare name calls phplyr’s function. Write a leading backslash to call the built-in, as in \count($array).

phplyr functions Where they are documented
count, rename Single-table functions
min, max Vector helpers
abs, sqrt, exp, log, log10, round, floor Expressions
str_replace, str_split, str_pad Strings and dates
extract, chop, pack, unpack tidyr

A file that doesn’t import these names is not affected.

Loading data

phibble builds tables from CSV files, PDO queries, query builders, and PHP arrays:

$schools = DataFrame::fromCsv('schools.csv');
$rows = DataFrame::fromRows([['id' => 1, 'x' => 2.5], ['id' => 2, 'x' => null]]);
$cols = DataFrame::fromColumns(['id' => [1, 2], 'x' => [2.5, null]]);

null is a missing value, R’s NA. A DataFrame is immutable, so every function returns a new table and leaves its input unchanged. echo $table prints the first rows in the format of R’s tibble package.

Pipelines

A table function such as filter(...) returns a closure that takes a table and returns a new one. A pipeline applies such closures in order.

  • PHP 8.5+
  • PHP 8.3–8.4

The pipe operator |> calls the closure on its right with the value on its left:

$out = $schools |>
    filter(fn ($r) => $r->score > 80) |>
    arrange(desc('score'));

phplyr($table) starts a method chain. Each method calls the phplyr function of the same name with the same arguments. A chained method is camelCase, so group_by() is ->groupBy() and n_groups() is ->nGroups(). get() returns the table:

$out = phplyr($schools)
    ->filter(fn ($r) => $r->score > 80)
    ->arrange(desc('score'))
    ->get();

The two forms give the same result, and the documentation shows both.

A method chain stays a chain while each method returns a table. These functions return something else, and the chain returns that value:

Functions Return
pull(), group_vars(), group_size(), group_indices(), group_rows(), group_split(), group_map() An array
n_groups() An integer
setequal() A boolean
show_query() The SQL string
lm(), glm(), lmer(), glmer() phit’s result array

echo prints a chain’s table without get(). ->pipe($closure) applies a closure of your own and continues the chain with its result.

pipe() applies closures in order on every PHP version:

$out = pipe($schools, filter(fn ($r) => $r->score > 80), arrange(desc('score')));

Columns, row closures, and vector helpers

Columns are named with strings: 'score' where dplyr takes a bare score.

A row closure is an ordinary PHP closure. It receives the row as a Phibble\Row, whose columns read as $r->score or $r['score'], and the table of the row’s group as a second argument:

mutate(gap: fn ($r) => $r->score - $r->prior_score)
filter(fn ($r, $group) => $r->score > mean('score')($group))

A vector helper is one of phplyr’s functions for whole columns, such as lag('x'), cumsum('x'), min_rank('x'), or mean('x'). It is evaluated once per group. A summary helper in mutate() gives one value per group, and that value is repeated on every row of the group:

  • PHP 8.5+
  • PHP 8.3–8.4
$schools = DataFrame::fromCsv('schools.csv') |> group_by('school');

echo json_encode([
    'groups' => $schools |> group_vars(),
    'n_groups' => $schools |> n_groups(),
    'sizes' => \array_slice($schools |> group_size(), 0, 4),
]), "\n\n";

// Grouped mutate: helpers are evaluated within each group.
echo $schools |>
    mutate(centered: fn ($r, $g) => round($r->score - mean('score')($g), 2), rank_in_school: min_rank(desc('score'))) |>
    ungroup() |>
    head(4);

// One table per group.
$parts = $schools |> group_split();
echo "\n", \count($parts), ' tables; the first has ', $parts[0]->nrow(), " rows\n";
$schools = phplyr(DataFrame::fromCsv('schools.csv'))->groupBy('school')->get();

echo json_encode([
    'groups' => phplyr($schools)->groupVars(),
    'n_groups' => phplyr($schools)->nGroups(),
    'sizes' => \array_slice(phplyr($schools)->groupSize(), 0, 4),
]), "\n\n";

// Grouped mutate: helpers are evaluated within each group.
echo phplyr($schools)
    ->mutate(centered: fn ($r, $g) => round($r->score - mean('score')($g), 2), rank_in_school: min_rank(desc('score')))
    ->ungroup()
    ->head(4);

// One table per group.
$parts = phplyr($schools)->groupSplit();
echo "\n", \count($parts), ' tables; the first has ', $parts[0]->nrow(), " rows\n";

The first argument of a vector helper is the column. It can be a column name, col('x'), another helper, or a row closure. Later arguments are values, so a string there is a literal. Wrap a string in col() to refer to a column.

A third form, col('x')->mul(2), builds an expression. Expressions give the same results as the helpers in memory, and they let a pipeline run as SQL on a database table. See Databases and expressions.

Named arguments and options

Functions that create columns name them with PHP named arguments: mutate(total: ...), summarize(n: n()). An option that dplyr writes with a leading dot, such as .by, is written with a leading underscore, such as _by:. Any other named argument is a column, so mutate(_before: 'id') places the new columns and mutate(before: 1) makes a column called before. Underscored arguments lists them.

PHP does not allow positional arguments after named ones. Put across() and other positional arguments first: summarize(across(...), n: n()).

Printing and inspecting

echo prints a table. glimpse() prints one line per column and returns the table unchanged, so it can sit inside a pipeline. pull('x') returns a column as a PHP array, and $table->toRows() returns every row as an array.
