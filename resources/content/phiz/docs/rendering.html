Specifications

toArray() returns the Vega-Lite specification and toJson() encodes it. Plots also implement JsonSerializable. The specification declares the Vega-Lite 6 schema.

These escape hatches reach the parts of Vega-Lite that phiz does not wrap:

  • raw([...]) deep-merges arbitrary Vega-Lite into the top level. Nested objects merge, and lists and scalars replace.
  • transform(...) adds Vega-Lite transforms that run before every layer.
  • layer([...]) adds a raw Vega-Lite layer.
  • param() and select() add raw parameters.

In the browser

embed() returns a chart container followed by the script tags, and html() returns a complete page. Both take vega-embed options, such as ['actions' => false] or ['renderer' => 'svg'].

The container holds the specification in a data-phiz attribute. phiz’s loader script draws every such container with vega-embed and redraws it when the attribute changes, so the same markup works in static pages, Blade views, and Livewire components.

Library sources and offline pages

By default the page loads vega, vega-lite, and vega-embed from the jsDelivr CDN, with subresource integrity, so it needs a network connection. Assets chooses another source:

Source Use
Assets::cdn() jsDelivr (the default)
Assets::local('/js/vega') copies you serve: vega.min.js, vega-lite.min.js, vega-embed.min.js
Assets::inline('/path/to/js') the libraries embedded in the page, for files that work offline
Assets::none() none; your bundle already sets window.vegaEmbed
false the container alone, without scripts 
use Phiz\Assets;$page = $plot->html(assets: Assets::inline('/path/to/js'));file_put_contents('chart.html', $page);

save('chart.html') always uses the CDN.

Static export

svg(), png(), pdf(), and save() with an image extension run the vl-convert binary, which renders without a browser.

$plot->save('figure.svg');$plot->save('figure.png', scale: 3);file_put_contents('figure.pdf', $plot->pdf());
  • Finding the binary. phiz checks the PHIZ_VL_CONVERT and VL_CONVERT environment variables, then PATH. A missing binary throws Phiz\Exceptions\VlConvertNotFound with installation instructions.
  • Options. new Export(binary:, timeout:, fontDir:) sets the binary path, the timeout, and an extra font directory.

Installing vl-convert

vl-convert has no Homebrew formula or apt package. Each release ships a self-contained binary for macOS (osx-arm64, osx-64) and Linux (linux-64, linux-aarch64). The Linux binaries link only against glibc and zlib, so they run on a bare Ubuntu image with no fonts or other packages installed. On Ubuntu the install is:

curl -sSLo /tmp/vl-convert.zip https://github.com/vega/vl-convert/releases/download/v1.9.0/vl-convert_linux-64.zipsudo unzip -j -o /tmp/vl-convert.zip bin/vl-convert -d /usr/local/binvl-convert --version

On macOS, download vl-convert_osx-arm64.zip from the same release and unzip it the same way. The macOS binary has only an ad hoc signature. A copy fetched with curl or gh release download is not quarantined and runs directly. If a browser download is quarantined, xattr -d com.apple.quarantine vl-convert clears the flag. Put the binary in a directory on PATH, or point PHIZ_VL_CONVERT at it.

Reproducible SVG

  • Repeated runs. With the same vl-convert version, the same specification gives the same SVG bytes on every run. Unseeded jitter is the exception: without seed:, jitter() uses Vega’s random(). With seed:, the offsets are part of the specification.
  • Fonts. vl-convert measures sans-serif text with its bundled Liberation Sans, so the layout does not depend on the fonts installed on the machine. The SVG keeps its text as <text font-family="sans-serif">, so the viewer’s browser chooses the displayed font. A theme that names another font, or an export with fontDir:, makes the layout depend on the fonts vl-convert can find.
  • Across machines. The visual tests render on macOS and on Linux in CI and compare both with the same PNG baselines, within a pixel tolerance.
  • Committed figures change when the specification, the vl-convert version, or its Vega-Lite version changes. Pin the vl-convert version wherever figures are generated.
