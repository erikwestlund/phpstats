Tests

composer test

The suite runs with Pest and covers several layers:

  • Spec snapshots for every geom, feature, statistics helper, and gallery example, in tests/.pest/snapshots/. After an intended change, run vendor/bin/pest --update-snapshots and review the diff.
  • Validation of every specification against the pinned Vega-Lite 6.1.0 JSON schema in tests/fixtures/.
  • Numerical checks of quantiles, least squares, smoothing bands, and predictions against values from R.
  • Blade component tests on Orchestra Testbench.
  • When vl-convert is available, a render of every gallery example to SVG. Some specifications pass the schema but fail to compile, and this smoke test catches them.

The statistics tests build model designs with Phit\model_matrix(). They run on the phit extension when it is loaded and on phpstats/phit-polyfill, a development dependency, when it is not. The saved fits in tests/fixtures/fits.json let them check results against R.

CI runs the suite on PHP 8.3, 8.4, and 8.5. The tests in tests/Pipes/ use the pipe operator, so phpunit.xml runs them only on PHP 8.5. Code in src/ must parse on PHP 8.3.

Evidence records

The Benchmarks and Verification pages on phpstats.org render JSON records from site/benchmarks/ and site/verifications/, listed in site/site.json. Generate them from a run, never by hand:

Command Writes
Rscript scripts/evidence/r-references.R tests/fixtures/r-references.json, the R reference values with the R and package versions
php scripts/evidence-parity.php the agreement-with-R records, comparing phiz with those references (tests/Spec/EvidenceParityTest.php runs the same checks in CI)
php scripts/evidence-tests.php the schema, snapshot, pipe and method-chain, and export records, from a Pest run
php scripts/bench-large-data.php the large-data binning benchmark
php scripts/bench-build.php the small-plot build benchmark
php scripts/bench-export.php the vl-convert export benchmark

The benchmarks run each case in its own process under peakmem -l (from phpolars’ bench/csv-pipeline/peakmem.c). Published benchmark records come from the Linux benchmark machine.

Gallery

php examples/gallery.php [output.html] [--svg=dir]

The gallery writes an HTML page of every example in examples/catalog.php, with each example’s code. The catalog is a plain PHP array, so other projects can reuse it.

Documentation

The documentation is a Quarto website in docs/. The pages include generated fragments for their examples:

  1. Each file in docs/examples/ returns a chart. An example that uses the pipe operator has a method-chain twin, {name}.chain.php, and the page shows the two in tabs labeled “PHP 8.5+” and “PHP 8.3–8.4”. A {name}-preview.php file shows only its chart, and {name}-hero.php shows its chart before the code.
  2. The pages under docs/examples/ show complete scripts from docs/examples/scripts/. The generator runs each in an empty directory beside vendor, displays it without the opening tag and autoloader, and shows the chart it produced.
  3. php scripts/docs-examples.php runs every example and checks that each twin builds the same specification. It writes the code and the chart to docs/_generated/, and an SVG to docs/figures/ when vl-convert is found. It also writes the gallery fragment from examples/catalog.php. Charts are sized to the page by scripts/docs-fit.php: a plot without a width fills the content column.
  4. php scripts/docs-reference.php writes the API reference fragments from the signatures and docblocks in src/. A function without a docblock gets a generated description: a fill or y twin points to its color or x original, and a pipe wrapper to its method. Write a docblock for anything else.
  5. quarto render docs builds the site into docs/_site/.
  6. scripts/render-docs runs steps 3 to 5, then copies the site into docs/.

phpstats.org imports the committed HTML in docs/ and publishes it at https://phiz.phpstats.org/docs, so commit the rendered pages with their sources. GitHub Pages serves only redirects: .github/workflows/pages.yml generates one for each page in docs/, pointing to the same page on phpstats.org. The pipe examples need PHP 8.5, and the SVGs need vl-convert 1.9.0, the version the committed figures were made with:

PHP=php8.5 PHIZ_VL_CONVERT=/path/to/vl-convert scripts/render-docs

A render rewrites every lastmod in docs/sitemap.xml from the file times on the rendering machine. Keep the committed dates, and change the date only for pages whose content changed.

Some statistics examples build designs from model formulas with Phit\model_matrix(). phit-polyfill provides it when the phit extension is not loaded, so the documentation build needs no extension.

Design notes and plans that are not user documentation live in notes/.
