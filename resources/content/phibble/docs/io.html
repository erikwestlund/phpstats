Read and write CSV and JSON, and load query results from databases.

CSV files

DataFrame::fromCsv() reads delimited text the way readr’s read_csv() and read_delim() do. DataFrame::fromCsvString() reads from a string. fromCsv() takes:

  • a path, decompressing files that end in .gz,
  • an http:// or https:// URL, which needs PHP’s allow_url_fopen. The file is downloaded to a temporary file, read, and deleted, and a failed download throws with the URL and the reason,
  • an open stream.
$url = 'https://vincentarelbundock.github.io/Rdatasets'    .'/csv/carData/Mroz.csv';$mroz = DataFrame::fromCsv($url);

Guessing

Without explicit types, phibble guesses each column from up to guessMax rows, sampled the way readr 2 samples them. A column is:

  • bool if every value is T, F, TRUE, FALSE, True, False, true, or false,
  • int if every value is a whole number (readr guesses double),
  • float if every value is a number, including Inf and NaN,
  • date if every value is an ISO 8601 date,
  • datetime if every value is an ISO 8601 date and time,
  • time if every value is a time of day as readr reads one: hours of one or two digits, a colon, two digits of minutes, and optionally seconds, a fraction, and AM or PM, such as 7:30, 00:07:15, or 1:30 PM,
  • string otherwise.

Numbers with leading zeros such as 007 stay strings, as in readr.

As in readr, a time’s minutes and seconds must be under 60, 12 AM is hour 0, PM adds 12 hours to any hour but 12, and a fraction of a second is dropped. The phit extension has no time type, so phibble guesses times in the columns phit reads as text, from the same rows the PHP reader samples.

Parse problems

When a value cannot be parsed as its column’s type, a row has the wrong number of fields, or a quoted field is never closed, phibble still returns the data. The value becomes NA, and the read raises one E_USER_WARNING that lists the problems. Rows are numbered as in readr::problems(): the first data row is row 2, and skipped, blank, and comment lines are not counted.

Quotes

Quoted fields follow readr 2’s rules. A field is quoted when its first character is the quote character. Inside a quoted field, a doubled quote is a literal quote. Any other quote turns quoting off or back on and is dropped, so "x "y" z" reads as x y z, and "x "y",z" reads as x y,z. A quote inside a field that does not start with one is kept as it is. With escapeDouble: false, the quotes inside a quoted field are kept, and only the opening and closing quotes are dropped.

Files written with PHP’s fputcsv() and its default backslash escape contain \" instead of "". readr does not treat the backslash as an escape, and neither does phibble unless escapeBackslash: true is passed.

set_error_handler(function (int $level, string $message): bool {    echo "Warning: {$message}\n";    return true;});$df = DataFrame::fromCsvString(    "id,score\n1,2.5\n2,oops\n3\n",    types: ['score' => 'double'],);echo $df;

Large CSV files

Reading in chunks

DataFrame::fromCsvChunked() reads a file a chunk of rows at a time, as readr’s read_delim_chunked() does. It passes each chunk to a callback with the 1-based index of the chunk’s first row, and stops if the callback returns false. DataFrame::csvChunks() returns the same chunks as a generator keyed by that index. Memory depends on the chunk size, so a file larger than the memory limit can be filtered down as it is read:

$chunks = DataFrame::csvChunks(    'feed.tsv',    chunkSize: 10_000,    delimiter: "\t",    types: ['.default' => 'c'],);$kept = [];foreach ($chunks as $chunk) {    $kept[] = $chunk->filter(col('category')->eq('Running'));}$running = DataFrame::concat($kept);

Types not given are guessed from the first chunk, and every later chunk is parsed as those types. As in readr, guessMax defaults to the chunk size. Give every type, as above, to skip guessing. A value in a later chunk that does not fit its column’s type becomes NA. Factors without levels take their levels from each chunk.

Every other option works as it does in fromCsv(). Each chunk’s problems raise their own warning, with rows numbered from the start of the file.

With the phit extension loaded, chunks are read natively with Phit\CsvReader, with the same results as the PHP reader.

Memory

A whole-file read holds every value as an element of a PHP array, with either reader, so its memory grows with the file. fromCsvChunked() holds one chunk at a time, so its memory follows the chunk size. An aggregate that can be combined, such as a count or a sum, can be computed for each chunk and the results added up. This script counts the penguins of each species, 100 rows at a time:

$totals = [];$count = function (DataFrame $chunk) use (&$totals) {    $counts = $chunk        ->groupBy(['species'])        ->summarize(['n' => n()]);    foreach ($counts as $row) {        $totals[$row->species] ??= 0;        $totals[$row->species] += $row->n;    }};DataFrame::fromCsvChunked('penguins.csv', $count, chunkSize: 100);ksort($totals);echo tibble(    species: array_keys($totals),    n: array_values($totals),);
# A tibble: 3 × 2
  species       n
  <chr>     <int>
1 Adelie      152
2 Chinstrap    68
3 Gentoo      124

For a file too large to hold as PHP arrays, keep the data in Polars, and only the result comes back to PHP. PolarsTable keeps phibble’s and phplyr’s API, as the Backends page describes. phpolars’ lazy CSV example queries a large file with Polars’ own API.

Writing CSV

writeCsv($path) writes a file and toCsv() returns the text. The format follows readr’s write_csv(). Values are quoted only when needed, NA is written as NA, logicals as TRUE and FALSE, dates in ISO 8601, and datetimes in UTC with a Z. Times are written as hms writes a column: one number of fraction digits for the column, and hours padded with spaces to one width. Factors are written as their labels, and list-columns throw.

$df = tribble(    ['name', 'note', 'score', 'seen'],    ['Ana', 'likes "quotes"', 1e5, true],    ['Ben', 'a, b', null, false],);echo $df->toCsv();
name,note,score,seen
Ana,"likes ""quotes""",100000,TRUE
Ben,"a, b",NA,FALSE

The options are delimiter, na, append, colNames, quote ('needed', 'all', or 'none'), escape, and eol.

Writing and reading JSON

toJson() writes a list of records, and toJson('columns') writes an object of columns. NA is written as null and kept in every record. DataFrame::fromJson() reads either shape and detects which one it has.

$df = tibble(id: [1, 2], score: [2.5, null]);echo $df->toJson(), "\n";echo $df->toJson('columns'), "\n";echo DataFrame::fromJson('{"id": [1, 2], "ok": [true, null]}');
[{"id":1,"score":2.5},{"id":2,"score":null}]
{"id":[1,2],"score":[2.5,null]}
# A tibble: 2 × 2
     id ok   
  <int> <lgl>
1     1 TRUE 
2     2 NA

Databases

Query results

DataFrame::fromPdo() runs a query with positional or named bindings and loads the result. PostgreSQL and MySQL report each column’s declared type, and phibble uses it:

Declared type Column type
Text types, JSON, UUID, TIMETZ, intervals, arrays, and enums string
BOOLEAN (PostgreSQL) bool
Integer types and MySQL’s YEAR int
REAL, DOUBLE PRECISION, FLOAT, and DOUBLE float
NUMERIC and DECIMAL float, or int when every value is a whole number
DATE date
TIMESTAMP, TIMESTAMPTZ, and DATETIME datetime
TIME time

A text column stays text, so 'TRUE' and '2024-01-02' in a TEXT column are strings. Only values without a declared type are guessed with the CSV rules. SQLite stores values without a column type, so its results are always guessed, and so are results from other drivers.

NUMERIC and DECIMAL values become doubles, as RPostgres and RMariaDB read them:

  • A value of up to 15 significant digits, such as a NUMERIC(10,2) price, reads back as the same decimal. Arithmetic on it is floating-point.
  • A longer value is rounded: 12345678901234567.89 reads as 12345678901234568.0.
  • A string type keeps the database’s exact decimal text.
$accounts = DataFrame::fromPdo(    $pdo,    'SELECT id, balance FROM accounts',    types: ['balance' => 'string'],);

Explicit types always take precedence over declared ones. fromQuery(), the Laravel ->toDataFrame() macro, and SqlTable::collect() follow the same rules.

$pdo = new PDO('sqlite::memory:');$pdo->exec('CREATE TABLE visits (    id INTEGER, clinic TEXT, bp REAL, seen TEXT)');$pdo->exec("INSERT INTO visits VALUES    (1, 'north', 121.5, '2024-05-01'),    (2, 'south', NULL, '2024-05-02'),    (3, 'north', 133.0, '2024-05-02')");$df = DataFrame::fromPdo(    $pdo,    'SELECT * FROM visits WHERE clinic = ?',    ['north'],);echo $df;
# A tibble: 2 × 4
     id clinic    bp seen      
  <int> <chr>  <dbl> <date>    
1     1 north   122. 2024-05-01
2     3 north   133  2024-05-02

Query builders

DataFrame::fromQuery() loads a query builder without depending on its library:

  • A Laravel query builder, Eloquent builder, or relation is read through toSql(), getBindings(), and its connection’s PDO object.
  • A Doctrine DBAL QueryBuilder is read through getSQL() and getParameters(). Pass a PDO or DBAL connection as the second argument to run the SQL through PDO. Without one, the builder runs the query itself and phibble guesses every column, since DBAL results carry no column types.

To keep a query in the database and run verbs there, use a SQL table instead.

Laravel collections

DataFrame::fromCollection() reads any object with an all() or toArray() method, such as a Laravel Collection. The items may be arrays, objects, or Eloquent models. toCollection() returns an Illuminate\Support\Collection of row arrays and throws when Laravel is not installed.

$collection = new class{    public function all(): array    {        return [            ['id' => 1, 'name' => 'Ana'],            (object) ['id' => 2, 'name' => 'Ben'],        ];    }};echo DataFrame::fromCollection($collection);
# A tibble: 2 × 2
     id name 
  <int> <chr>
1     1 Ana  
2     2 Ben
