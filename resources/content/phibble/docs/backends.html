Run the same pipeline in memory, in a database, or in Polars. Every verb is part of the Phibble\Contracts\Table interface, and three classes implement it:

Backend Class Runs Use it for
In memory Phibble\DataFrame PHP arrays Small and medium data, closures, anything
SQL Phibble\Sql\SqlTable SQLite, PostgreSQL, or MySQL Data that lives in a database
Polars Phibble\Polars\PolarsTable Polars, through the php_polars extension from phpolars Large data in memory

Code written against Table, including phplyr’s verbs, runs on any of them. A backend that cannot run a step exactly, such as a PHP closure or a function with no exact translation, loads its rows into PHP and runs the step in a DataFrame. Later steps also run in memory. Results match DataFrame with these exceptions:

  • A database cannot represent some of R’s values, such as NaN in MySQL. The SQL tables page lists these cases.
  • Rows from a SQL join, and from a SQL table without arrange(), come back in the order the database returns them.
  • Floating-point results can differ in the last digits. The SQL and Polars tests compare floats rounded to nine decimal places.

The Table contract page states the rules each backend follows.

Choosing and switching

use Phibble\DataFrame;use function Phibble\{tbl, polars};use function Phibble\Expr\{col, mean, n};$df = DataFrame::fromCsv('sales.csv');$sql = tbl($pdo, 'sales');$fast = polars($df);$summary = fn ($t) => $t    ->filter(col('units')->gt(0))    ->groupBy(['store'])    ->summarize(['n' => n(), 'avg' => mean(col('price'))]);$summary($df);$summary($sql)->collect();$summary($fast)->collect();
  • On $sql, the summary runs as one SQL query.
  • collect() turns any table into a DataFrame. polars() and PolarsTable::fromTable() move a table into Polars, and tbl() opens a database table or query.
  • The Table interface declares only summarise(). Code that accepts any Table should call it, although all three classes also have summarize().

The Polars backend

PolarsTable loads only when used, so phibble runs without the extension.

  • Expressions, joins (including join_by comparisons and rolling joins), pivots, and the lubridate and stringr functions run in Polars.
  • Steps it cannot run, such as PHP closures and str_to_title(), run in a DataFrame. PolarsTable::$fallbacks counts them.
  • PolarsTable::$strict = true throws PolarsFallback instead, naming the verb and the reason.

Type mapping:

  • A time column is a Polars duration in microseconds, which, like an hms, can be negative or longer than a day. A Polars Time column reads as a time.
  • Comparisons of times, is_na(), min(), max(), first(), and last() run in Polars. Other functions of a time run in a DataFrame, as do sum(), mean(), median(), quantile(), sd(), var(), and iqr() of dates and datetimes.
  • fromTable() throws on a list-column of named arrays with different keys, since Polars structs have every key in every row, and on a list-column of DataFrames.

The Polars test suite runs phibble’s dplyr, tidyr, lubridate, and stringr reference cases on PolarsTable and skips when the extension is not loaded.
