Phibble\Sql\SqlTable is a table backed by a SQL query, like dbplyr’s tbl(). Methods called with expressions compile to SQL for SQLite, PostgreSQL, or MySQL, and the database runs the query when the rows are needed.

Opening a table

Call Source
tbl($pdo, 'name'), SqlTable::table() A table or view.
tbl($pdo, 'SELECT ...', $bindings), SqlTable::query() A query with positional (?) or named (:name) bindings.
SqlTable::fromQuery($builder) A Laravel or Doctrine query builder.
SqlTable::fromSource($pdoSource) A PdoSource.

Which calls query the database:

  • Opening a table reads its column names with a LIMIT 0 query. In SQLite, which declares no column types, it also reads the first 1,000 rows to guess date, datetime, and time columns.
  • nrow() and count() run a COUNT(*) query, and types() collects the first 1,000 rows.
  • collect(), toRows(), column(), iteration, and printing load the rows.
  • Other methods and showQuery() run nothing. showQuery() returns the SQL with ? placeholders, and bindings() returns their values in order.

This example queries an in-memory SQLite table, penguins, loaded from penguins.csv:

What compiles to SQL

select(), rename(), filter(), mutate(), arrange(), groupBy(), summarize(), distinct(), slice(), head(), and join() compile when their arguments are expressions or column names. The compiled SQL keeps R’s semantics:

  • An aggregate returns NA when its group contains NA, unless na_rm: true. phibble adds a check on the count of non-NULL values, since SQL aggregates skip NULL.
  • Cumulative functions return NA after the first NA.
  • Ranks leave NA rows unranked.
  • isIn() never returns NA.
  • / returns a float, and division by zero gives NA.
  • Groups in summarize() output are sorted, with NA last.
  • Text compares in byte order and case-sensitively, through COLLATE "C" in PostgreSQL and utf8mb4_0900_bin in MySQL.

When the table falls back to memory

When an argument has no faithful SQL translation, the SqlTable runs the query so far, collects its rows into PHP, and runs the method in memory. The method returns a DataFrame, so every later step also runs in memory, with DataFrame’s values apart from the known differences. Here mul() compiles, and round() and a closure fall back:

$pdo = new PDO('sqlite::memory:');$t = tbl($pdo, <<<'SQL'    SELECT 1 AS id, 2.5 AS x    UNION ALL SELECT 2, 3.5    SQL);$doubled = $t->mutate(['y' => col('x')->mul(2)]);$rounded = $t->mutate(['y' => Phibble\Expr\round(col('x'))]);$closure = $t->filter(fn ($r) => $r->x > 3);echo get_class($doubled), "\n";echo get_class($rounded), "\n";echo get_class($closure), "\n";echo $rounded;

SQLite column types

SQLite compares by storage class, and it orders all text above all numbers. A column declared without a type stores bound values as text, so col('x')->gt(0) is true for every row of such a column. Declare column types (INTEGER, REAL, TEXT) when creating SQLite tables that phibble will query.

Known differences

These cases can differ from DataFrame, because the database cannot represent R’s result:

  • MySQL has no infinity or NaN. Results that are Inf, -Inf, or NaN in R, such as x / 0, log(0), or mean() of no values, are NA in MySQL. SQLite stores infinities but has no NaN, so NaN is NA there.
  • Integer arithmetic beyond 64 bits fails in the database, where DataFrame switches to a double.
  • Joins do not warn about unexpected many-to-many matches.
  • Column names starting with __phibble_ are reserved for the hidden columns that keep row order and window results.

Row order and window functions

SQL tables have no row order of their own. phibble numbers the rows of the source query when the table is opened and keeps that number through every step.

  • Collected rows follow arrange(), and otherwise the source order. arrange() is stable, so ties keep the source order.
  • The source order is the order in which the database returns the source query’s rows. A stored table does not fix it, so add arrange() when the order matters.
  • Rows from a SQL join have no defined order.
  • Window functions such as lag() and cumsum() use order_by: where given, then the arrange() order, then the source order.
  • Grouped mutate() and filter() compile to OVER (PARTITION BY ...).
$pdo = new PDO('sqlite::memory:');$sales = tbl($pdo, <<<'SQL'    SELECT 'a' AS store, 1 AS week, 10 AS units    UNION ALL SELECT 'a', 2, 14 UNION ALL SELECT 'a', 3, 9    UNION ALL SELECT 'b', 1, 7 UNION ALL SELECT 'b', 2, NULL    SQL);$out = $sales    ->groupBy(['store'])    ->arrange(['store', 'week'])    ->mutate([        'running' => cumsum(col('units')),        'of_best' => col('units')            ->div(max(col('units'), na_rm: true)),    ]);echo $out->showQuery(), "\n\n";echo $out->collect();

Joins

join() between two tables on the same PDO connection compiles to a SQL join. The output columns follow DataFrame::join(): x’s columns, then y’s other columns, with .x and .y suffixes on clashing names. NA keys match each other, as in dplyr, through IS in SQLite, IS NOT DISTINCT FROM in PostgreSQL, and <=> in MySQL. Pass naMatches: false for SQL’s usual equality.

$pdo = new PDO('sqlite::memory:');$visits = tbl($pdo, <<<'SQL'    SELECT 1 AS clinic_id, 120 AS bp    UNION ALL SELECT 2, 135    UNION ALL SELECT NULL, 128    SQL);$clinics = tbl($pdo, <<<'SQL'    SELECT 1 AS id, 'north' AS name    UNION ALL SELECT NULL, 'unassigned'    SQL);$joined = $visits    ->join($clinics, [['clinic_id', 'id']], 'left');echo $joined->showQuery(), "\n\n";echo $joined->arrange(['bp'])->collect();

Dialects
