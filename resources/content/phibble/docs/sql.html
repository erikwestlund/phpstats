Phibble\Sql\SqlTable is a table backed by a SQL query, like dbplyr’s tbl(). It implements the same Table contract as DataFrame. Verbs called with expressions are compiled into SQL, and no query runs until the rows are needed. SQLite, PostgreSQL, and MySQL are supported.

Opening a table

tbl($pdo, 'name') opens a table or view. tbl($pdo, 'SELECT ...', $bindings) starts from a query with positional (?) or named (:name) bindings. The same tables can be opened with SqlTable::table() and SqlTable::query(). SqlTable::fromQuery($builder) starts from a Laravel or Doctrine query builder, and SqlTable::fromSource($pdoSource) from a PdoSource.

phibble reads the column names when the table is opened. It runs the query itself when the rows are needed: collect() returns a DataFrame, and toRows(), nrow(), iteration, and printing also run it.

showQuery() returns the SQL with ? placeholders, and bindings() returns their values in order.

// Load penguins.csv into an in-memory SQLite database.$pdo = new PDO('sqlite::memory:');$pdo->exec('CREATE TABLE penguins (species TEXT, island TEXT, bill_len REAL, bill_dep REAL,    flipper_len INTEGER, body_mass INTEGER, sex TEXT, year INTEGER)');$insert = $pdo->prepare('INSERT INTO penguins VALUES (?, ?, ?, ?, ?, ?, ?, ?)');foreach (DataFrame::fromCsv('penguins.csv')->toRows() as $row) {    $insert->execute(array_values($row));}$penguins = tbl($pdo, 'penguins');$summary = $penguins    ->filter(col('year')->eq(2008))    ->groupBy(['species'])    ->summarize(['n' => n(), 'mass' => mean(col('body_mass'), na_rm: true)]);echo get_class($summary), "\n\n";echo $summary->showQuery(), "\n\n";echo json_encode($summary->bindings()), "\n\n";echo $summary->collect();

Each verb wraps the previous query in a subquery, so each step’s SQL stays simple. Database planners usually flatten the nesting.

What compiles to SQL

These verbs compile when their arguments are expressions or column names: select(), rename(), filter(), mutate(), arrange(), groupBy(), summarize(), distinct(), slice(), head(), and join().

The compiled SQL keeps R’s semantics:

  • An aggregate returns NA when its group contains NA, unless na_rm: true. SQL aggregates skip NULL, so phibble adds a check on the count of non-NULL values.
  • Cumulative functions return NA after the first NA.
  • Ranks leave NA rows unranked.
  • isIn() never returns NA.
  • / returns a float, and division by zero gives NA.
  • Groups in summarize() output are sorted, with NA last.

When the table falls back to memory

Some arguments have no faithful SQL translation. A SqlTable then collects the rows and runs the verb in memory, and the verb returns a DataFrame. The values are then those DataFrame computes, apart from the known differences below. The fallbacks are:

  • any PHP closure,
  • round(), because SQL’s ROUND does not round half to even,
  • as_string() and as_bool(),
  • paste() and paste0() with arguments other than text literals, because SQL formats numbers differently from R,
  • regular-expression patterns, except str_detect() in MySQL (which uses ICU, as stringr does). Patterns wrapped in fixed(), and plain patterns without regular-expression characters, are translated everywhere,
  • str_extract(), str_extract_all(), str_split(), str_split_i(), str_to_title(), center str_trunc(), and str_pad(side: 'both'); str_pad() and str_squish() in SQLite; str_to_upper() and str_to_lower() in SQLite, whose UPPER() and LOWER() change only ASCII letters,
  • parsing text to dates (ymd() and the others) on columns, floor_date(), ceiling_date(), round_date(), period arithmetic, with_tz(), and force_tz(), because the result type depends on the column type, which SQL tables do not track. Date parts (year() and the others), wday(), and difftime() are translated; a call on literals only, such as ymd('2024-01-01'), is evaluated once and passed as a value,
  • functions of a PostgreSQL time or MySQL TIME column other than comparisons and is_na(), because SQL’s time functions differ from lubridate’s (MySQL’s HOUR() of 25:00:00 is 25),
  • any use of SQLite text that holds times, such as 7:30:00, because it sorts and compares as text. SQLite columns are guessed as dates, datetimes, or times from their first 1000 rows when the table is opened,
  • sum(), mean(), median(), quantile(), sd(), var(), and iqr() of date, datetime, and time columns, which keep R’s types in memory,
  • first(), last(), and nth() without a row order (from arrange() or order_by:), or with default: or na_rm:,
  • iqr() outside PostgreSQL, cumprod(), and consecutive_id(),
  • sd() and var() in SQLite, whose formula would lose precision,
  • str_trim(), because R removes all Unicode white space and SQL TRIM removes spaces,
  • nested aggregates such as mean(x - mean(x)), summarize() entries that are not one value per group, and slice() with negative positions,
  • median() and quantile() outside PostgreSQL,
  • quantile() without na_rm: true,
  • median(), quantile(), and n_distinct() inside grouped mutate() or filter(), because SQL has no window form of them,
  • take(), eachGroup(), rowwise(), mutateGroups() with closures, and filterGroups(),
  • joins with multiple, relationship, or unmatched set, joins between different connections, full joins in MySQL, and full joins with NA matching in PostgreSQL.

SQLite compares by storage class, and it orders all text above all numbers. A column declared without a type stores bound values as text, so col('x')->gt(0) is true for every row of such a column. Declare column types (INTEGER, REAL, TEXT) when creating SQLite tables that phibble will query.

Known differences

These cases can differ from DataFrame, because the database cannot represent R’s result:

  • MySQL has no infinity or NaN. Results that are Inf, -Inf, or NaN in R, such as x / 0, log(0), or mean() of no values, are NA in MySQL. SQLite stores infinities but has no NaN, so NaN is NA there.
  • Integer arithmetic beyond 64 bits fails in the database, where DataFrame switches to a double.
  • Joins do not warn about unexpected many-to-many matches.
  • Column names starting with __phibble_ are reserved for the hidden columns that keep row order and window results.

Text compares in byte order and case-sensitively, as R does: phibble applies COLLATE "C" in PostgreSQL and utf8mb4_0900_bin in MySQL to text columns wherever values are compared, sorted, grouped, or joined.

Window functions

Grouped mutate() and filter() compile aggregates and window functions to OVER (PARTITION BY ...). Window functions such as lag() and cumsum() need a row order. SQL tables have none, so phibble numbers the rows of the source query when the table is opened and keeps that number through every step. Windows use the order_by: option where given, otherwise the order set by arrange(), and otherwise the source order. The same order decides the order of collected rows and breaks ties after arrange(), which is stable as in dplyr. The source order is the order in which the database returns the source query’s rows. For a stored table, add arrange() to make it explicit.

$pdo = new PDO('sqlite::memory:');$sales = tbl($pdo, <<<'SQL'    SELECT 'a' AS store, 1 AS week, 10 AS units    UNION ALL SELECT 'a', 2, 14 UNION ALL SELECT 'a', 3, 9    UNION ALL SELECT 'b', 1, 7 UNION ALL SELECT 'b', 2, NULL    SQL);$out = $sales    ->groupBy(['store'])    ->arrange(['store', 'week'])    ->mutate([        'running' => cumsum(col('units')),        'of_best' => col('units')->div(max(col('units'), na_rm: true)),    ]);echo $out->showQuery(), "\n\n";echo $out->collect();

Joins

join() between two tables on the same PDO connection compiles to a SQL join. The output columns follow DataFrame::join(): x’s columns, then y’s other columns, with .x and .y suffixes on clashing names. NA keys match each other, as in dplyr, through IS in SQLite, IS NOT DISTINCT FROM in PostgreSQL, and <=> in MySQL. Pass naMatches: false for SQL’s usual equality. The order of rows from a SQL join is not defined, so call arrange() when it matters.

$pdo = new PDO('sqlite::memory:');$visits = tbl($pdo, "SELECT 1 AS clinic_id, 120 AS bp UNION ALL SELECT 2, 135 UNION ALL SELECT NULL, 128");$clinics = tbl($pdo, "SELECT 1 AS id, 'north' AS name UNION ALL SELECT NULL, 'unassigned'");$joined = $visits->join($clinics, [['clinic_id', 'id']], 'left');echo $joined->showQuery(), "\n\n";echo $joined->arrange(['bp'])->collect();

Dialects

Dialect::for($pdo) chooses the dialect from the PDO driver. The dialects differ in identifier quoting, cast types, string functions, and NULL-safe equality. The SQL for one expression in each dialect:
