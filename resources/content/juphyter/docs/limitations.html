A cell cannot redeclare a class or a function

PHP cannot redeclare a class, interface, trait, enum, or function in the same kernel process. Restart the kernel before running a changed definition.

The kernel refuses such a cell before executing anything and names the collision:

RedeclarationError: The class, interface, trait or enum "Widget" was already
declared in this session, and PHP cannot redeclare it. Restart the kernel to
redefine it.
  • A cell that failed to declare anything leaves the name free. After class Widget extends Typo {} throws, the corrected cell runs.
  • Cells run out of order recover the same way. A subclass cell run before its base class fails, and runs once the base class cell has run.
  • A conditional declaration is bound at run time and is not refused:
if (! function_exists('helper')) {    function helper() { /* ... */ }}

A cell cannot declare a namespace

A namespace declaration is refused, because changing namespace part way through a session breaks name resolution for everything already defined. Use fully qualified names, or use statements, which carry from one cell to the next.

Every cell runs under strict types

The kernel prepends declare(strict_types=1); to each cell.

  • A cell that declares strict_types=1 itself runs, and the kernel removes the duplicate.
  • declare(strict_types=0) and declare(encoding=...) are refused, because PHP accepts them only as a file’s first statement.
  • declare(ticks=...) is left alone.

References and $this do not carry between cells

Variables carry across cells by value. A reference taken in one cell is an ordinary copy in the next. $this has no meaning at a notebook’s top level. Objects, arrays, scalars, and resources persist normally.

A closure called from another cell has no line in its traceback

A traceback names the cell and the line for functions and methods, across cells:

RuntimeException: from the function
  at Cell 1, line 3, in boom()
  at Cell 2, line 2

PHP’s trace does not say where a closure was declared, and every cell shares one file name, so a closure declared in one cell and called from another is reported without a location. The call site is still reported:

LogicException: from the closure
  in a closure
  at Cell 4, line 4

A cell whose value is null shows no output

var_dump($x);, Juphyter\display($df), and any other call that returns nothing produce no Out[N]. Every other value is shown, including 0, false, '', [], and 'null'.

exit and die end the kernel

PHP cannot catch either, so the kernel process ends. The cell’s earlier output is shown, followed by:

SystemExit: The cell ended the kernel process with exit or die, so nothing
further can run. Restart the kernel to carry on.

Interrupting needs pcntl

The stop button sends a signal, so the PHP binary that runs the cells needs the pcntl extension with its functions callable. juphyter install and juphyter doctor warn when it is missing or listed in disable_functions. Enable pcntl for that binary, or run juphyter install --php with a binary that has it.

An interrupt arrives as Juphyter\Engine\Interrupt, which extends Error rather than Exception. A cell that catches Throwable in a loop can still swallow it.

HTML tables format numbers differently from the text output

A data frame’s text/plain output is phibble’s own. The HTML table formats a float with PHP’s string conversion instead of phibble’s significant-figure rules, so a dbl column can read differently in the two. Round values that are meant for display. The HTML header also omits the group count that the text output shows.

macOS and Linux only

The kernel interrupts a cell with POSIX signals, which the Windows PHP build does not provide, and the engine talks to the Python transport over a Unix socket. juphyter is tested on macOS and Linux. The Windows Subsystem for Linux has not been tested.

Not supported

  • Documentation on hover. Jupyter’s inspect_request is not answered, so shift-tab shows nothing.
  • Reading input. A cell cannot prompt, so readline() and fgets(STDIN) have nothing to read.
  • Magics. There are no %-prefixed commands.
  • Widgets. ipywidgets is not supported.
  • The debugger. Jupyter’s debug protocol is not implemented, so JupyterLab’s debugger does not attach.
