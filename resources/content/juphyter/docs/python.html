Two Python interpreters take part in running a PHP document:

Interpreter Chosen by Needs
The kernel’s juphyter install, recorded in the kernelspec ipykernel 7.0 or later
Quarto’s Quarto, at each render jupyter_client, nbformat, nbclient, and pyyaml

The environment that juphyter install --create-venv builds has all of these, because it holds JupyterLab. JupyterLab starts each kernel with the interpreter its kernelspec names, so it needs no further setup.

When Quarto’s interpreter has no Jupyter, a render stops with Jupyter kernel 'php' not found. Point Quarto at the environment with one of the fixes below.

How Quarto chooses an interpreter

Measured with Quarto 1.10.18. The first match wins:

Order Source
1 QUARTO_PYTHON in the environment
2 QUARTO_PYTHON in a project _environment file beside _quarto.yml
3 The first python3 on PATH

Quarto does not read VIRTUAL_ENV, does not fall back to python, and ignores RETICULATE_PYTHON.

juphyter doctor prints the interpreter Quarto will use in its Quarto section. quarto check jupyter 2>&1 reports it from Quarto’s side, and a Jupyter: (None) line means that interpreter has no Jupyter.

At a terminal

For the current shell, put the environment first on PATH with the export line that juphyter doctor prints, or activate it:

source ~/.venvs/juphyter/bin/activatequarto render notebook.qmd

For one command:

QUARTO_PYTHON=~/.venvs/juphyter/bin/python quarto render notebook.qmd

For every render in one Quarto project, put an _environment file beside _quarto.yml, with an absolute path:

QUARTO_PYTHON=/Users/you/.venvs/juphyter/bin/python

Setting QUARTO_PYTHON or the environment’s PATH entry in a shell startup file changes the interpreter for every Quarto project on the machine. juphyter writes neither to a startup file.

VS Code and Cursor

  1. Open the document’s folder as a workspace. A .qmd opened on its own has no workspace folder for the Quarto extension to ask about.
  2. Run Python: Select Interpreter and choose an environment that has Jupyter, such as ~/.venvs/juphyter.

The Quarto extension passes that choice to Quarto as QUARTO_PYTHON on every render in the workspace, so a project _environment file cannot override it. Correct a wrong selection in the interpreter picker.

Positron

The steps are the same as in VS Code: open the folder, then run Python: Select Interpreter.

  • A workspace that already has an interpreter stored keeps it. python.defaultInterpreterPath in .vscode/settings.json applies only when none has been selected.
  • A change to that setting takes effect after Developer: Reload Window.
  • Each render opens a new terminal, where echo "QUARTO_PYTHON=[$QUARTO_PYTHON]" shows the interpreter Positron passed. An empty value means none is selected.

Other editors

An editor without Quarto integration, such as PhpStorm or RStudio, leaves the choice to PATH. Activate the environment before starting the editor, or set QUARTO_PYTHON in its terminal or run configuration. Quarto does not read the Python preference that RStudio stores.
