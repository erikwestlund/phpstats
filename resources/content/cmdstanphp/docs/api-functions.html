CmdStan 2.37 is the oldest supported release, as in CmdStanR 1.0. set_cmdstan_path() refuses an older installation, discovery skips one, and install_cmdstan() rejects older versions. CI tests 2.37 and 2.40. Options added in newer CmdStan releases fail on older ones with CmdStan’s error message.

Data and CSV files

Function Result
write_stan_json(data, file, alwaysDecimal: false, variables: null) Writes data, initial values, or a metric as JSON. data may be an array, a StanData, or a table. With variables (stanc’s declarations, such as $model->variables()['data']), int variables are written as integers and tuples as Stan’s {"1": ..., "2": ...} objects.
read_cmdstan_csv(files) A fit from one or more CmdStan CSV files (.csv, .csv.gz, or .csv.bz2)
as_cmdstan_fit(files, variables: null, checkDiagnostics: true, format: null) The same, reading only variables and with format as the fit’s default draws format
read_cmdstan_csv_list(files, variables: null, samplerDiagnostics: null, format: null) CmdStanR’s read_cmdstan_csv() list shape
draws_to_csv(chains, dir) Writes [chain][iteration][variable] draw rows to one CSV file per chain

Data arrays are named PHP arrays at the top level, with lists for Stan arrays, vectors, and matrices:

  • Matrices are lists of rows, with no column-major conversion. Booleans become 0 and 1, complex numbers are [re, im] pairs, and a tuple is a list of its elements. Empty top-level data becomes {}.
  • Missing values, strings, objects, nonfinite numbers, sparse indices, invalid variable names, and ragged arrays are rejected, and the error names the variable.
  • The fitting methods write data with the model’s declarations. Every declared data variable is required, int variables are written as integers (a non-integer is truncated with a warning), and a single value for a one-dimensional array becomes a one-element array.
