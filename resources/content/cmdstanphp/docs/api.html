All classes and functions are in the CmdStan namespace. Standalone functions keep CmdStanR’s snake_case spelling. Methods, parameters, and properties are camelCase, as PSR-1 and this family’s conventions require, so CmdStanR’s fit$output_files() is $fit->outputFiles(); the compatibility contract maps every renamed method. CmdStan option names are unchanged. Inference methods accept PHP named arguments or one associative options array; they reject unknown options instead of silently ignoring them. null generally leaves the installed CmdStan default in effect. Check the compatibility contract for exceptions.

Global options

options() accepts cmdstanr_output_dir, cmdstanr_write_stan_file_dir, cmdstanr_force_recompile, cmdstanr_draws_format, cmdstanr_warn_inits, cmdstanr_verbose, cmdstanr_no_ver_check, cmdstanr_max_rows, cmdstanr_print_line_numbers, mc.cores, and cmdstanphp_example_dir. A null value unsets an option. Unknown names and values of the wrong type throw. mc.cores sets the default parallel_chains and installer core count.

Data arrays use named PHP arrays at the top level and zero-indexed lists for Stan arrays, vectors, and matrices. Boolean values become 0/1. Matrices are rows of rows, with no R column-major conversion. Empty top-level data becomes {}. Missing values, strings, objects, nonfinite numbers, sparse indices, invalid variable names, and ragged arrays are rejected.

Model methods

stanFile(), exeFile(), hppFile(), and code() return paths or source text. exposeFunctions(timeout: null) compiles the model’s user-defined functions and returns a StanFunctions object; functions() returns it afterwards. modelName(), hasStanFile(), cppOptions(), and includePaths() expose model identity and recorded compiler settings. print(lineNumbers: false) writes source to stdout. saveHppFile(dir) copies the generated header. variables() returns stanc’s JSON information for source-level declarations and dimensions. format(overwriteFile: false, stancOptions: []) returns formatted Stan and optionally overwrites the source. checkSyntax(stancOptions: []) throws on invalid Stan and returns true on success.

compile(forceRecompile: null, stancOptions: [], cppOptions: [], cores: 1, timeout: null) compiles via CmdStan’s makefile and returns the model. Compiler options use associative arrays, e.g. ['warn-pedantic' => true] or ['STAN_THREADS' => true]. Make values containing command expansions or shell metacharacters are rejected. stanc option values with whitespace are not supported. Changing options removes stale model artifacts before rebuilding.

sampleMpi(mpiCmd: 'mpiexec', mpiArgs: [], ...options) accepts sampling options, defaults to one chain, and executes chains sequentially. Fit methods

  • draws(variables: null, format: null, incWarmup: false): select posterior variables. Formats are draws_array, draws_matrix, draws_df, draws_list, and draws_rvars; null uses the cmdstanr_draws_format option or the method default.
  • samplerDiagnostics(format: null, incWarmup: false): diagnostic columns ending in __, excluding lp__.
  • summary(variables: null, probs: [0.05, 0.95], measures: []): descriptive and MCMC convergence summaries, or the requested summary measures.
  • diagnosticSummary(): per-chain num_divergent, num_max_treedepth, and ebfmi arrays.
  • checkDiagnostics(checks: ['divergences', 'treedepth', 'ebfmi']), diagnosticWarnings(): check and read messages.
  • cmdstanDiagnose(): invoke CmdStan’s diagnostic utility and return text.
  • metadata(), chainMetadata(), variables(), numChains(), numDrawsSampling(), numDrawsWarmup(): inspect parsed CSV.
  • stepSize(), invMetric(matrix: true): adaptation results, one entry per chain.
  • time(): per-chain warmup, sampling, and total time when available.
  • output(), returnCodes(): captured console output and process status. Imported fits have no process logs or status codes.
  • outputFiles(), latentDynamicsFiles(), profileFiles(), profiles(): output paths and parsed profiling data. The file accessors accept includeFailed for CmdStanR compatibility; fits only contain successful runs. Latent-dynamics and profile accessors throw when no such files exist.
  • dataFile(), configFiles(), metricFiles(), cmdstanConfig(), metric(): data and auxiliary JSON paths and their decoded contents. Imported fits use the data file recorded in the CSV when it still exists.
  • code(), numProcs(), lp(), cmdstanSummary(): stored source, number of processes, log-density matrix, and native text summary. Imported CSV fits do not include source code.
  • saveOutputFiles(), saveLatentDynamicsFiles(), saveProfileFiles(), saveDataFile(), saveConfigFiles(), saveMetricFiles(): each takes dir: '.', basename: null, timestamp: true, random: true and names files basename-YYYYmmddHHMM-id-xxxxxx.ext as CmdStanR does. Files created by the run are moved; imported and user-supplied files are copied. Existing destinations are never overwritten.
  • saveObject(file): serialize parsed fit data (and native MCMC summary statistics) to a PHP object file.
  • print(variables: null, maxRows: null): emit summary JSON to stdout, limited to cmdstanr_max_rows (default 10) variables.
  • drawsColumns(), summaryColumns(), drawsTable(), summaryTable(): column-oriented draws and summaries for data frames; see data frames.

Model methods

These methods need PHP FFI. The first call compiles a shared library for the fit’s model and data; initModelMethods(seed: 1, verbose: false, hessian: false, model: null) does this explicitly. Imported CSV fits must pass model:.

  • logProb(unconstrainedVariables, jacobian: true): log density with constants dropped.
  • gradLogProb(...): ['log_prob' => float, 'gradient' => list].
  • hessian(...): ['log_prob' => float, 'grad_log_prob' => list, 'hessian' => rows].
  • unconstrainVariables(variables): a flat unconstrained list from parameter values keyed by name.
  • unconstrainDraws(files: null, draws: null, format: null, incWarmup: false): the fit’s draws, another set of CSV files, or draws_df rows, in unconstrained space.
  • constrainVariables(unconstrainedVariables, transformedParameters: true, generatedQuantities: true): variables keyed by name as nested arrays.
  • variableSkeleton(transformedParameters: true, generatedQuantities: true): variable name to dimension list.
  • exposeFunctions(timeout: null) / functions(): the model’s user-defined functions.

jacobianAdjustment is accepted as a deprecated alias of jacobian. CmdStan\ModelMethods and CmdStan\StanFunctions can also be used directly with a Stan file.

Method-specific fit methods

CmdStanMCMC adds loo(variables: 'log_lik', rEff: true, momentMatch: false, maxIters: 30, kThreshold: null, split: true, cov: true) and waic(variables: 'log_lik'). Both return estimates (each with Estimate and SE), pointwise rows, and flat keys such as elpd_loo and se_elpd_loo; LOO also returns diagnostics with Pareto k values. momentMatch: true needs model methods and the phit posterior-draw kernels, and adds a moment_match key; see the inference guide.

CmdStanMLE adds mle()/optimizedParams() (final optimizer row) and lp(); its summary() returns variable/estimate rows, matching CmdStanR’s optimization summary. CmdStanVB adds variationalMean() and lpApprox(). Pathfinder and Laplace also expose lpApprox(); Laplace exposes mode(), and generated quantities fits expose fittedParamsFiles(). CmdStanPathfinder adds singlePathFiles(), singlePathJsonFiles(), singlePathFits(), and singlePathDiagnostics() for runs with save_single_paths: true. CmdStanDiagnose adds gradients() (gradient-check console output).

Statistics helpers

CmdStan\Figure renders computed figures with ascii(), vegaLite(), json(), html(), svg(), and png(); casting a figure to a string gives its ASCII form. CmdStan\Plot computes the figures, plus bandwidth(), density(), autocorrelation(), and ranks() for the values they draw. CmdStan\Psis (paretoSmooth(), paretoKhat(), psis(), gpdfit()), CmdStan\Loo (loo(), waic(), relativeEff()), CmdStan\MomentMatch (loo() on unconstrained draws with log-density and log-likelihood callbacks, fromFit()), CmdStan\DrawKernels (detection of and wrappers for the phit draw kernels), CmdStan\Summary (summarise() and each posterior measure), CmdStan\Rvars, and CmdStan\Inits (fromFit(), fromDraws(), nest(), validate()) operate on plain draws arrays. Their docblocks describe the input and output shapes.

Data frames and the phpstats family

CmdStanPHP works with the phpstats family without depending on it. phibble is detected by method and class names. The phit extension is detected by function name.

Data in

Every data argument (sample(), sampleMpi(), optimize(), variational(), pathfinder(), laplace(), generateQuantities(), diagnose(), and logProb()) and write_stan_json() accept a plain array, a JSON file, a CmdStan\StanData, or a table. A table is any object with toModelData() or toColumns(), such as a phibble Phibble\DataFrame. toModelData() is used when both exist. StanData::fromTable($table, addN: true) performs the same conversion and keeps the factor labels.

Column Stan data
int or float The list of values, unchanged
bool 0/1 integers
list cells Nested arrays, which must be rectangular
factor 1-based integer indices in level order, plus J_<name>, the number of levels
string A factor with sorted unique levels (strcmp order, as phibble’s and R’s factor() defaults)
null, dates, other objects Rejected with the column name and row, because Stan data has no missing values

Factor levels come from a toModelData() descriptor (['levels' => list<string>, 'codes' => list<?int>, 'ordered' => bool], with 0-based codes, as phibble’s DataFrame::toModelData() returns them since phibble 93858fa; add 'base' => 1 for 1-based codes) or, for a toColumns() table, from levels($name) when types() reports a factor. The ordered flag is ignored. Labels cannot be written to Stan JSON, so they are returned in StanData::$levels, keyed by data variable, where label i has index i + 1. The conversion adds N, the row count, unless the table has a column named N, and adds J_<name> unless a column already has that name. CmdStan ignores data variables that the program does not declare. Column names must be valid Stan identifiers.

Fit methods are camelCase, as are StanData‘s and Tables’ from...() constructors and the package’s other static helpers, such as CmdStanFit::fromCsv() and Inits::fromFit(). StanData is a value object with readonly data, levels, columns (the names of the columns of X), and meta. toArray() returns data, and with(['prior_scale' => 2.5]) adds or replaces variables.

Regression data

StanData::fromColumns($columns, y: 'y', x: ['x1', 'x2'], groups: 'school', intercept: false) builds the usual hierarchical regression data block from named columns or a table:

Variable Contents
N Number of rows
K Number of predictors (columns of X)
X N rows of K floats, in the order of x
y The outcome, keeping integers as integers
<g>_id For each grouping column g, the 1-based group index of each row
J_<g> For each grouping column, the number of groups
J The number of groups, when there is exactly one grouping column

Groups are numbered over sorted unique values (numbers numerically, otherwise in strcmp order) or over a factor’s levels, and the labels are in levels['<g>_id']. Predictors must be numeric. intercept: true prepends a column of ones named (Intercept). It is off by default because Stan programs usually give the intercept its own parameter.

$data = CmdStan\StanData::fromColumns($df, 'score', ['hours'], 'school');
$fit = $model->sample(data: $data, seed: 1);
data {
  int<lower=0> N;
  int<lower=0> K;
  matrix[N, K] X;
  vector[N] y;
  int<lower=1> J;
  array[N] int<lower=1, upper=J> school_id;
}

StanData::fromFormula('y ~ x1 + f + (1 + x1 | g)', $data, dropIntercept: false, missing: 'drop') builds regression data from an R-style formula through Phit\model_matrix() in the phit extension (phit 741d38f and later). The function handles factor predictors (treatment contrasts), interactions, transforms, and offsets, and keeps the (Intercept) column in X unless dropIntercept: true. $data can be columns, factor descriptors, or a table, whose toModelData() is passed unchanged. Without the function, fromFormula() throws a RuntimeException that names the requirement. StanData::fromModelMatrix($result) maps an existing Phit\model_matrix() result and is the only code that depends on its shape.

Formula part Stan data
Design matrix N (retained rows), K, and X; the column names are in columns
Numeric response y, as integers when every value is integral, so it suits int and real declarations
Factor response y as 0/1 for two levels (Bernoulli), or 1..C with C levels (categorical); labels in levels['y']
cbind(s, f) response y (successes) and trials (successes plus failures)
offset() offset
(... \| g) <g>_id (1-based) and J_<g> per grouping factor, and J when there is one grouping factor
Random slopes, such as (1 + x \| g) Z_<g> (N rows of the group’s columns, including the intercept column) and Q_<g>, the number of columns; omitted when every term on the group is intercept-only

Group names that are not Stan identifiers have other characters replaced by _, so the nested group g2:g1 gives g2_g1_id. Groups are numbered in factor level order when the data has descriptors or table factors, and otherwise over sorted labels (numbers numerically, otherwise byte order, as Phit\model_matrix() sorts levels). Terms on the same group are concatenated into one Z_<g>, intercept-only terms included, so (1 | g) + (0 + x | g) gives the same Z_g as (1 + x | g). Two groups whose names map to the same <g>, such as a.b and a_b, are rejected. Factors reach Phit\model_matrix() as descriptors in the data’s level order, so the first level is the reference level and a factor response is coded in that order, while plain string columns use sorted levels. missing: 'drop' removes rows with missing values in any variable the formula uses, with one E_WARNING from Phit\model_matrix(), and missing: 'raise' rejects them. The remaining result keys, including retained_rows, dropped_rows, n_input, n_dropped, terms, and assign, are kept in meta, and meta['random'][<g>] lists each group’s columns and terms.

data {
  int<lower=0> N;
  int<lower=1> K;
  matrix[N, K] X;          // includes the intercept column
  vector[N] y;
  int<lower=1> J;
  array[N] int<lower=1, upper=J> g_id;
  int<lower=1> Q_g;
  matrix[N, Q_g] Z_g;      // (1 + x1 | g)
}

Draws and summaries out

  • drawsColumns(variables: null, incWarmup: false) returns draws as columns, like posterior’s as_draws_df(): one list per variable element (such as beta[2]), then one-based .chain, .iteration, and .draw columns.
  • summaryColumns(variables: null, probs: [0.05, 0.95], measures: []) returns summary() as columns: variable and one column per measure.
  • drawsTable() and summaryTable() take the same arguments and return a Phibble\DataFrame built with DataFrame::fromColumns(). They need phpstats/phibble, which requires PHP 8.5, and throw a RuntimeException explaining this when it is not installed.
  • CmdStan\Tables::fromRows($rows) converts any list of associative rows, such as loo()['pointwise'], to columns.

The column arrays need no other package and suit any data frame library that accepts name-to-values columns.

Part of the phpstats family

CmdStanPHP is part of the phpstats family of PHP statistics packages:

  • phit: the phit native extension (Phit\ functions), which provides the moment-matching draw kernels and, when available, Phit\model_matrix().
  • phibble: data frames (Phibble\DataFrame).
  • phplyr: dplyr-style verbs for phibble tables.
  • phiz: a Vega-Lite grammar of graphics.

The family packages target PHP 8.5. CmdStanPHP keeps PHP 8.2 support and requires none of them.

Errors

Invalid PHP data or options throw InvalidArgumentException. Missing files/toolchain, timeouts, and malformed CSV throw runtime errors. A nonzero command exit throws ProcessException, whose public readonly properties are command, exitCode, stdout, and stderr. A failing chain terminates other active chains; partial output files remain available for investigation. Partial outputs are not returned as a successful fit.
