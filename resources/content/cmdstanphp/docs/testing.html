Local verification

composer install
composer validate --strict
composer lint
composer test
export CMDSTAN=/absolute/path/to/cmdstan-2.40.0
composer test:integration
composer test:compatibility   # additionally needs R + cmdstanr, posterior, loo, bayesplot, jsonlite, Rcpp, RcppEigen

The unit suite does not need CmdStan. Moment-matching tests also need the phit extension with its posterior-draw kernels (for example php -d extension=/path/to/libphit.dylib vendor/bin/phpunit) and skip without it. It verifies JSON shapes and invalid data, CSV comments/warmup/special numbers, draw layouts, summaries, diagnostics, serialization, option validation, process argument isolation, pipe draining, timeouts, cancellation, and bounded execution. It uses real PHP subprocesses for process behavior. Data frame interoperability is tested with stand-in tables and a stand-in Phibble\DataFrame, so phibble is not needed. Without phit, StanData::fromFormula() is tested with a stand-in Phit\model_matrix(). With it, the tests cover random intercepts and slopes, factor predictors and responses, and dropped rows against the real function.

The integration suite compiles the bundled models and invokes real CmdStan methods. It compares Bernoulli posterior estimates with their analytic mean, checks R-hat and ESS, verifies deterministic seeds with parallel chains, confirms modes and draw counts, and exercises generated quantities, fixed parameters, syntax/formatting, gradient checking, log density, input errors, metrics, and auxiliary files. It fits a hierarchical regression built with StanData::fromColumns(), runs a model on table data, and, when phit is loaded, fits score ~ study_hours + (1 | school) built with StanData::fromFormula() on phit’s schools data and compares the posterior means with Phit\fit_lmer(). It also builds FFI libraries for model methods and exposed functions, initializes chains from fits, runs the example models, and computes LOO with and without moment matching. Tests that need FFI skip when it is unavailable. If CmdStan is not available, PHPUnit skips these tests; CI explicitly installs CmdStan so they execute there.

Tests use small models and a modest number of draws. They do not constitute a full upstream CmdStanR conformance suite, do not test a real MPI cluster or OpenCL hardware, and do not establish native Windows support. The package’s compatibility contract lists remaining gaps.

The compatibility suite runs the same algorithms with CmdStanR and PHP using identical seeds and precision, then compares individual parameter/log-density draws, approximate densities, descriptive summaries, R-hat, bulk/tail ESS, and MCMC diagnostics. MCMC comparisons include even and odd chain lengths. Further comparisons cover CSV metadata keys, in-process log densities, gradients, Hessians, constrain/unconstrain results, exposed Stan functions, PSIS, LOO, LOO moment matching, WAIC, relative efficiency, and posterior summary measures. Moment matching is compared with loo::loo_moment_match.default() on analytic regression posteriors, both unmodified and with loo’s split step corrected as documented, and with CmdStanR’s loo(moment_match = TRUE) on a same-seed fit. The values behind the figures are compared with R and bayesplot. R, CmdStanR, posterior, loo, bayesplot, jsonlite, Rcpp, and RcppEigen are needed. These tests skip when their prerequisites are absent.

The moment-matching reference was verified with CmdStanR 0.9.0 and two loo 2.10.1.9000 development builds: 7991145, from before stan-dev/loo#405, and fd910fe, which includes it. The isolated R reference in tests/fixtures/moment_match.R records the loo version and commit and contains the explicit split-inverse and two-half efficiency corrections. With an earlier loo, the suite checks that loo’s own split differs where a shift is combined with scaling or a covariance map. With a corrected loo, it checks that loo’s own split matches CmdStanPHP for every design. Transform-order preservation also has an independent regression test.

Continuous integration

.github/workflows/tests.yml runs unit tests on PHP 8.2, 8.3, and 8.4. A separate integration matrix builds CmdStan 2.37 and 2.40 on Linux, runs the real-model suite, and caches each toolchain. The integration jobs enable PHP’s FFI extension and render every figure kind to SVG, and one to PNG, with a downloaded vl-convert binary. The 2.40 job additionally installs the reference R packages and runs the compatibility suite. Installation is performed using this package’s installer to exercise its download/build path. Compilation on small CI machines is memory-intensive; integration uses two make jobs.

The integration jobs build phit from the pinned phpstats/phit commit b71e406ee58fc7a255687514b2818c3c615a517b, which adds Phit\model_matrix() and Phit\fit_lmer() (the draw kernels and Phit\dist_normal_rng() are unchanged since e7457cb), using PHP 8.4 headers to match the runner. They require all three draw kernels, FFI, the seeded draw generator, Phit\model_matrix(), and Phit\fit_lmer() before running native unit tests (including StanData::fromFormula() against the real function), real-model tests, and (on CmdStan 2.40) R comparisons. These runs fail on skipped tests. The real-model run excludes the compatibility group until R is installed. The lightweight unit matrix still tests the optional-extension path without phit. Local native tests must likewise use a PHP executable matching the extension module ABI; a Homebrew PHP 8.5 extension cannot load into Herd PHP 8.4.

Documentation site

All site content is under docs/, written in Quarto. Each page is a .qmd source with its rendered .html committed beside it, which is also the layout the phpstats.org site reads when it imports a package’s documentation. No page executes code, so rendering needs neither CmdStan nor a Stan toolchain.

To render the site after editing a page:

quarto render docs
rsync -a --exclude '.DS_Store' docs/_site/ docs/

Quarto writes the rendered site to the untracked docs/_site, and the second command publishes it beside the sources. Both commands are needed. The render step deletes the published pages and site_libs/ from docs/, so running it without the rsync leaves the rendered site staged only under docs/_site. Commit the regenerated .html files along with search.json, sitemap.xml, robots.txt, and site_libs/ whenever a source page changes. To preview while editing, run quarto preview docs.

Links between pages are written as relative .qmd targets, which Quarto renders as relative .html links. The site therefore works at a domain root, at a repository subpath, and when phpstats.org imports the rendered pages.

.github/workflows/pages.yml checks the committed site’s internal links with scripts/check-docs.py on pull requests and on main, so a broken link is caught before publication. These checks run even before GitHub Pages is enabled. A separate job publishes docs/ from main or a manual dispatch on main. Deployment uses GitHub’s Pages artifact and environment; no token beyond GITHUB_TOKEN is needed.

After pushing this repository through your normal workflow, select Settings → Pages → Build and deployment → Source → GitHub Actions. The workflow then handles the publication. Repository settings cannot be enabled by writing files alone, and no remote publication has been performed in this workspace.
