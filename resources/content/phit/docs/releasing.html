This page is for maintainers. It describes how release artifacts are built and checked.

Binary artifacts

Create the tested Linux binary bundle locally:

docker build --target binaries --output type=local,dest=.context/binaries \
  -f docker/Dockerfile .

The archive name includes the library version, PHP major/minor, architecture, NTS mode and Bookworm target. It contains phit.so, installation instructions, a manifest, the project MIT license and dependency notices. A separate SHA-256 file checks archive integrity. Dependency notices include the Cargo dependency closure and build dependencies; exact upstream MIT notices missing from published crate archives are preserved under third-party/ with provenance hashes.

Treat a binary as matching the manifest’s build environment. It is not a universal Linux file. Verify its checksum, use the matching PHP extension directory, enable it for the required SAPIs, restart workers and execute a real fit.

Versioned release process

The installer and FPM workflow (packaging.yml) builds and tests the extension on Linux x86_64 and aarch64 at PHP 8.3, 8.4 and 8.5, and prepares the binary archives. Pushing a vX.Y.Z tag starts the release workflow (release.yml):

  1. It runs the packaging matrix.
  2. It checks that the tag matches both crate versions and the MIT license, creates the source archive and its checksum, and tests installation from the extracted archive.
  3. It creates the GitHub release with the source archive, the six binary archives, their checksums and SHA256SUMS.
  4. It downloads the published assets and installs each binary in the matching PHP image.

Export rules remove generated website caches and figures from the source archive, and keep the source, locked dependencies, model fixtures, test data and their notices. Packagist reads the tag through the repository’s GitHub webhook.

Before tagging:

  1. Run ./scripts/check on the exact commit, and wait for CI on main.
  2. Set the same version in crates/stats-core/Cargo.toml and crates/php-extension/Cargo.toml, and update Cargo.lock.
  3. Tag the version commit with an annotated tag and push the tag.

Deployment verification

tests/deployment.php verifies extension identity/version, automatic-intercept OLS, and a closed-form Poisson log-exposure model. scripts/check-fpm sends an isolated FastCGI request; scripts/check-container checks the final runtime image using its normal FPM pool. The scripts compare CLI/FPM version, coefficients and fitted rate. They fail on a loader error or wrong output instead of trusting php -m.
