Build, check, and publish a phit release. This page is for maintainers.

Before tagging

  1. Set the same version in crates/stats-core/Cargo.toml and crates/php-extension/Cargo.toml, and update Cargo.lock.
  2. Run ./scripts/check on the exact commit, and wait for CI on main to pass.
  3. Tag the version commit with an annotated vX.Y.Z tag and push the tag.

Release workflow

The packaging workflow (packaging.yml) builds and tests the extension on Linux x86_64 and arm64 at PHP 8.3, 8.4, and 8.5, and prepares the binary archives. Pushing a vX.Y.Z tag starts release.yml:

  1. It runs the packaging matrix.
  2. It checks that the tag matches both crate versions and the MIT license, creates the source archive and its checksum, and tests installing from the extracted archive.
  3. It creates the GitHub release with the source archive, the six binary archives, their checksums, and SHA256SUMS.
  4. It downloads the published assets and installs each binary in the matching PHP image, by hand and with pie install. In an image without Rust, PIE must pick the prebuilt archive.

Packagist reads the tag through the repository’s GitHub webhook.

The source archive’s export rules remove generated website caches and figures. They keep the source, locked dependencies, model fixtures, test data, and their notices.

Binary artifacts

Build the tested Linux binaries locally with:

docker build --target binaries \  --output type=local,dest=.context/binaries \  -f docker/Dockerfile .
  • Archives are named as PIE expects for prebuilt binaries, for example php_phit-vX.Y.Z_php8.4-arm64-linux-glibc-nts.zip.
  • composer.json lists pre-packaged-binary first in download-url-method. On Linux, pie install phpstats/phit downloads the matching archive and builds from source only when none matches.
  • Each zip holds phit.so at its root, installation instructions, a manifest of the ABI and minimum glibc, the MIT license, and dependency notices. A separate SHA-256 file checks the archive.
  • The dependency notices cover the Cargo dependency closure and build dependencies. MIT notices missing from published crate archives are kept under third-party/ with provenance hashes.

A binary matches the build environment in its manifest. It is not a universal Linux file. To install one by hand, verify its checksum, copy it to the matching PHP extension directory, enable it for each SAPI that needs it, restart the workers, and run a real fit.

Deployment verification

Check What it does
tests/deployment.php Checks the extension’s identity and version, OLS with an automatic intercept, and a closed-form Poisson model with a log-exposure offset
scripts/check-fpm Sends a FastCGI request to an isolated PHP-FPM
scripts/check-container Checks the final runtime image through its normal FPM pool

The scripts compare the CLI and FPM versions, coefficients, and fitted rates. They fail on a loader error or wrong output, instead of trusting php -m.
