phit 0.4.0 renamed the model functions. The 0.3 names still work in 0.4 as deprecated aliases. Each call raises one E_USER_DEPRECATED that names the replacement and returns exactly the replacement’s result. phit 0.5 will remove them.

fit_ols is the one name that 0.3 and 0.4 both use, so during 0.4 it accepts both forms and dispatches on its first argument. A string, or the named arguments formula: and data:, is the formula fit. An array, or the named arguments x: and y:, is the 0.3 matrix fit. It returns fit_ols_matrix()’s result and raises one deprecation. A call never changes meaning. In phit 0.5, an array passed to fit_ols will be an error that names fit_ols_matrix().

Phit\fit_ols(mixed $formula = null, mixed $data = null, string $missing = 'drop', mixed $weights = null,    ?array $offset = null, bool $intercept = true, ?array $x = null, ?array $y = null): array;

offset and intercept belong to the matrix form. A formula writes them as offset() and - 1. Mixing the two forms, such as a formula with x:, throws code 1001.

fit_mixed_logistic has no family or link arguments. The deprecated fit_glmer still accepts them and throws code 1007 for anything but the binomial family with the logit link.

All estimators are synchronous and stateless: each returns a complete fit without retaining a model handle, input data or mutable configuration. It does not mutate the caller’s arrays. Repeated fits are independent.

Formula interfaces

The formula functions parse an R model formula, build R’s model.matrix() over named columns, and call the estimation cores of fit_ols_matrix, fit_logistic_matrix, fit_probit_matrix, fit_poisson_matrix, fit_mixed_gaussian_matrix, and fit_mixed_logistic_matrix. Each fit returns the complete result contract of its matrix function. It adds formula, response, columns (coefficient names in coefficient order), terms, assign, intercept, and named (column => coefficient). fit_generalized_linear and fit_mixed_logistic also return family and link. model_matrix returns y, x (including the (Intercept) column), the naming keys, offset, random designs in the shape fit_mixed_gaussian_matrix accepts, and the deletion accounting.

Missing-value deletion covers only the variables a formula uses, with the same warning, missing: 'raise' behavior, and row accounting as the matrix functions. model_matrix keeps unused factor levels, as model.matrix() does. The fitting functions drop them, as lm(), glm(), and lme4 do. Unknown columns, malformed factor descriptors, referenced list-columns, and invalid formulas raise 1001. Column-length mismatch raises 1002. Infinite transform results raise 1003. Unsupported functions, families, links, and random-effect structures raise 1007. Rank deficiency raises 1004. The formula guide defines the syntax, contrasts, data shapes, verification, and every known difference from R.

Fixed intercept

The seven matrix estimators take bool $intercept = true. Supply predictor columns only: the binding prepends an exact ones column and the estimated intercept is coefficient 0, followed by predictors in supplied column order. Covariance, standard errors, tests and intervals follow that same order. Parameter counts and residual degrees of freedom include the added coefficient. No input array is mutated.

intercept: false passes the supplied x matrix literally. It is both the opt-out for a through-origin model and the compatibility option for callers already supplying a complete design with ones. There is no automatic detection of existing constant columns: leaving ones in x with the default creates a duplicate intercept and a rank-deficiency error, rather than silently guessing intent.

For an intercept-only fit, supply one empty predictor row per outcome, such as x: array_fill(0, count($y), []). An empty sample or ragged matrix is still invalid; empty predictor rows require intercept: true. Missing-row validation and deletion still apply to outcomes, predictors, groups, weights and offsets before fitting.

The Rust core takes the design literally.

Random-effect designs random[*].z remain explicit; this option only constructs the fixed design. For a random intercept/slope, z still needs [1, slope] rows.

Errors and conversion

The binding accepts actual integers and floats as numeric elements, with null and NAN representing missingness. PHP integers are converted to f64, so integers beyond the exact range of double precision may lose precision. Array keys and names do not label coefficients: row order aligns x with y, and column order aligns all coefficient results. Callers should normally supply packed lists and keep labels separately.

Missing values use listwise deletion by default, with one E_WARNING on a successful fit that omits rows. missing: ‘raise’ rejects missingness. Values are not coerced from strings, columns are not added, and aliased predictors are not removed. fitted and residuals follow retained_rows order. See Missing data for validation order, warnings, accounting and application handling. Applications can promote PHP warnings to exceptions.

Statistical and input failures use PHP Exception with stable numeric codes 1001–1008; see the diagnostic/error contract. There are no estimator-specific exception classes. Callers can inspect getCode() and should handle Throwable at their application boundary, since PHP argument and runtime errors use their own types. Message text may change. If the extension is absent, the functions themselves are unavailable; that is an installation failure rather than an invalid-data result.

NAN/INF are floating-point values in successful results, not failure sentinels. Serialization helpers may map them to null using a documented policy, while the native result preserves them. Current arithmetic uses f64; it is not arbitrary precision, and extreme input scales can exceed its range.

Rust boundary

pub fn fit_ols_matrix(    x: Vec<Vec<f64>>,    y: Vec<f64>,) -> Result<OlsResult, StatsError>

The core owns its inputs and has no PHP dependency. OlsResult exposes the same statistical fields as the PHP array (sample-deletion metadata is PHP-only), with Vec for numeric lists, Vec<Vec> for covariance, Vec<[f64; 2]> for confidence intervals, f64 for scalars, and usize for residual degrees of freedom. StatsError implements Display and Error. The binding converts errors and values without implementing statistical formulas.

See Design philosophy for the boundary between this raw API and optional convenience layers.

Diagnostics and error codes

Every successful estimator returns diagnostics:

Diagnostic key Contract
converged true on successful return, including direct OLS; failed fitting throws
solver scaled_svd, newton_irls, fisher_scoring, profile_variance_search, bobyqa or nelder_mead
iterations, evaluations Present only when the corresponding historical top-level key exists; same value, not a second counter
gradient_max Present for logistic mixed only; same scaled-coordinate finite-difference score as its top-level key
boundary, singular Present when the estimator already reports that flag; legitimate zero variance is permitted
warnings list; missing-row deletion, a reported near-singular covariance, or the logistic-mixed Laplace approximation advisory

Warnings in this array are interpretation notices. Only listwise deletion also emits the existing single PHP E_WARNING. Missing/undefined diagnostics are omitted; there is no fabricated iteration count or universal score. General Gaussian convergence still uses optimizer termination, parameter bounds, valid factors and finite output; it does not have a final variance-parameter gradient/Hessian gate. OLS has no iterative optimizer. Normal/Wald inference and local convergence do not guarantee model adequacy or quadrature accuracy.

Statistical and input failures throw PHP Exception with a numeric getCode():

Code Rust ErrorKind Meaning
1001 InvalidInput Type/domain/control error, missing=‘raise’, invalid groups/weights/counts
1002 DimensionMismatch Shape/alignment or insufficient residual observations
1003 Nonfinite Nonfinite values or arithmetic beyond floating-point range, including nonzero residual variance underflow
1004 RankDeficiency Numerical design/information rank failure
1005 FactorizationFailure Required linear solve or positive-definite information factor fails
1006 Nonconvergence Budget/line-search/optimizer/score failure, separation or unsupported finite optimum at a search boundary
1007 Unsupported Explicit size/count limit or unimplemented configuration
1008 Internal Required decomposition output missing or an internal mathematical invariant fails

Messages remain explanatory, not stable machine identifiers. Validation can report the first failed check when multiple problems exist; combined validation checks may use the most relevant category. Zend argument TypeError, result conversion/runtime errors, and caught Rust panics are runtime errors rather than statistical codes. Invalid data are checked before listwise deletion. Rust StatsError::new(kind, message) carries the explicit enum without classifying message text; .0 remains the display message and kind() exposes its category.

Binomial calls limit trials to 1,000,000 per original row, and accepted success-count rounding is canonicalized with round(y*trials)/trials. For exact zero-variance OLS, the existing NaN/INF conventions remain; nonzero variance underflow instead throws 1003. JSON consumers must handle documented undefined OLS quantities explicitly; PHP’s JSON_THROW_ON_ERROR rejects NaN/INF. See the v0.1 assessment for compatibility notes and tested stress ranges.
