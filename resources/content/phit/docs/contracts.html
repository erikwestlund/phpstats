Deprecated aliases

fit_lm, fit_glm, fit_lmer, fit_glmer, fit_logistic, fit_probit, fit_poisson, fit_mixed, fit_mixed_intercept, and fit_logistic_mixed, and fit_ols called with a matrix, still exist as deprecated aliases: each call raises E_USER_DEPRECATED that names the current function and returns its result.

Signatures

The formula functions are listed in Model formulas. The four fixed-effect matrix functions share one signature:

// fit_ols_matrix, fit_logistic_matrix,// fit_probit_matrix, fit_poisson_matrixPhit\fit_ols_matrix(    array $x,    array $y,    string $missing = 'drop',    ?array $weights = null,    ?array $offset = null,    bool $intercept = true,): array;

Matrix model functions lists the mixed-model matrix signatures.

Every estimator is synchronous and stateless:

  • It returns a complete fit and keeps no model handle, input data, or configuration.
  • It does not modify the caller’s arrays.
  • Repeated fits are independent.

Formula interfaces

The formula functions build R’s model.matrix() over named columns and fit it with the estimator of the matching matrix function. Each result has that matrix function’s complete contract plus naming keys (formula, response, columns, terms, assign, intercept, named, predvars, and, for fit_generalized_linear and fit_mixed_logistic, family and link).

Failure Code
Unknown column, malformed factor descriptor, referenced list-column, or invalid formula 1001
Columns of different lengths 1002

Model formulas defines the syntax, data shapes, contrasts, missing-value handling, and differences from R.

Matrix model contracts

Matrix model functions defines the inputs, results, convergence rules, and failure cases of each matrix function:

  • OLS
  • Binary logistic regression
  • Probit regression
  • Poisson regression
  • Gaussian random-intercept mixed model
  • Weights, offsets and grouped binomial responses
  • General Gaussian mixed model
  • Binomial random-intercept model

Fixed intercept

The seven matrix functions take bool $intercept = true.

  • With the default, supply predictor columns only. phit prepends an exact ones column, and the intercept is coefficient 0, followed by the predictors in column order. Covariance, standard errors, tests, and intervals follow the same order.
  • Parameter counts and residual degrees of freedom include the added coefficient.
  • intercept: false uses x exactly. Use it for a model through the origin, or for a design that already contains a ones column.
  • phit does not detect existing constant columns. Leaving a ones column in x with the default creates a duplicate intercept and raises a rank-deficiency error.
  • For an intercept-only fit, supply one empty predictor row per outcome, such as x: array_fill(0, count($y), []). Empty predictor rows require intercept: true.
  • Random-effect designs (random[*].z) are not affected. A random intercept and slope still needs [1, slope] rows.

Input conversion

  • Numeric elements must be PHP integers or floats. Values are not coerced from strings.
  • PHP integers are converted to 64-bit floats, so integers beyond 2^53 can lose precision.
  • Arrays are read in iteration order, and keys are ignored. Row order aligns x with y, and column order aligns every coefficient result. Keep labels separately.
  • null and NAN are missing. By default, rows with missing values are deleted with one E_WARNING, and missing: 'raise' rejects them. fitted and residuals follow retained_rows. See Missing values.
  • phit does not add columns or remove aliased predictors.
  • Arithmetic is 64-bit floating point. Extreme input scales can exceed its range.

Diagnostics and error codes

Exceptions

Statistical and input failures throw a PHP Exception with a numeric getCode():

Code Category Meaning
1001 Invalid input Type, domain, or control error; missing: 'raise'; invalid groups, weights, or counts
1002 Dimension mismatch Shape or alignment error, or too few residual observations
1003 Nonfinite Nonfinite values, or arithmetic beyond floating-point range, including nonzero residual variance that underflows
1004 Rank deficiency Numerical rank failure of the design or information
1005 Factorization failure A required linear solve or positive-definite factorization fails
1006 Nonconvergence Iteration budget, line search, optimizer, or score failure; separation; an optimum at a search boundary
1007 Unsupported An explicit size or count limit, or an unimplemented configuration
1008 Internal A required decomposition output is missing, or an internal invariant fails
  • There are no estimator-specific exception classes. Handle Throwable at the application boundary, since PHP argument and runtime errors use their own types.
  • Message text can change. Use the code, not the message.
  • When several checks fail, the exception can report the first, or the most relevant category.
  • Invalid data are checked before missing-value deletion.
  • Zend TypeError, result-conversion errors, and caught Rust panics are runtime errors, not statistical codes.
  • If neither the extension nor the polyfill is loaded, the functions do not exist. That is an installation failure.

Diagnostics

Every successful estimator returns diagnostics:

Key Contents
converged true on every returned fit, including direct OLS. A failed fit throws.
solver scaled_svd, newton_irls, fisher_scoring, profile_variance_search, bobyqa, or nelder_mead
iterations, evaluations Present when the result has the top-level key of the same name, with the same value
gradient_max Binomial mixed model only; the same value as its top-level key
boundary, singular Present when the estimator reports that flag. A zero variance is a valid fit.
warnings list<string>: missing-row deletion, a near-singular covariance, or the binomial mixed model’s Laplace advisory
  • The warnings are interpretation notices. Only missing-row deletion also raises a PHP E_WARNING.
  • Diagnostics that do not apply are omitted. phit does not invent an iteration count or a gradient.
  • General Gaussian mixed fits check optimizer termination, parameter bounds, valid factors, and finite output. They have no final gradient or Hessian check on the variance parameters.
  • Wald inference and local convergence do not establish model adequacy or quadrature accuracy.

Undefined values and limits

  • NAN and INF in a successful result are values, not failure markers. An exact zero-residual OLS fit keeps its documented NAN and INF statistics, while nonzero variance that underflows raises 1003.
  • PHP’s json_encode() with JSON_THROW_ON_ERROR rejects NAN and INF, so JSON consumers must handle them explicitly.
  • Binomial models allow at most 1,000,000 trials per original row. Accepted success counts are rounded with round(y*trials)/trials.

Implementation notes

The Rust core takes the design literally and has no PHP dependency:

pub fn fit_ols(    x: Vec<Vec<f64>>,    y: Vec<f64>,) -> Result<OlsResult, StatsError>
  • OlsResult has the statistical fields of the PHP array, with Vec<f64> for lists, Vec<Vec<f64>> for covariance, Vec<[f64; 2]> for confidence intervals, f64 for scalars, and usize for residual degrees of freedom. Missing-value deletion and its metadata exist only in the PHP binding.
  • StatsError::new(kind, message) carries an explicit ErrorKind. kind() returns the category, and .0 the message. The binding maps each ErrorKind to the codes above.
  • The binding converts values and errors. It does not implement statistical formulas.

See Design philosophy for the boundary between this API and optional convenience layers.
