This executable walkthrough uses saved simulated students. It derives the Bernoulli likelihood, shows the matrices and dot products, and follows Newton/IRLS iterations to the result returned by fit_logistic_matrix(). Production calculations live in crates/stats-core/src/logistic.rs; Python here makes the intermediate values visible. See setup.

1. Observations, parameters and probabilities

Each observation has study hours, a practice score and an observed pass/fail outcome. The supplied column of ones estimates an intercept. We simulate 80 students using R seed 20261012, with practice scores correlated with study hours:

\[\mathrm{score}_i=\operatorname{clip}(45+3\,\mathrm{hours}_i+e_i,20,95), \qquad e_i\sim N(0,8^2).\]

Hours are uniform between 1 and 12; hours and scores are rounded to two decimals. The true generating coefficients are \([-3.28,0.22,0.018]^\top\):

\[\eta_i=-3.28+0.22\,\mathrm{hours}_i+0.018\,\mathrm{score}_i, \qquad \pi_i=\frac{1}{1+e^{-\eta_i}},\qquad y_i\sim\operatorname{Bernoulli}(\pi_i).\]

A Bernoulli outcome is either 0 or 1. A probability such as 0.6 means a 60% chance of success under the model; the observed outcome is still a single 0 or 1. The generator is tests/generate-logistic-fixtures.R; the shared observations are in learning.csv. The estimates differ from the generating coefficients because they vary with the random sample.

The hand-worked iteration below starts from zero coefficients so the first weights and dot products are easy to inspect. phit also starts from zero, except for extreme inputs with a ones column, where it uses a finite marginal intercept start. Starting values change the iteration path, not the likelihood or the converged estimates.

2. Why model log-odds instead of the outcome directly?

OLS can produce fitted values outside \([0,1]\). Here the linear predictor \(\eta_i=x_i^\top\beta\) is mapped through the sigmoid, so \(0<\pi_i<1\) in exact arithmetic. Rearranging gives

\[\frac{\pi_i}{1-\pi_i}=e^{\eta_i},\qquad \log\frac{\pi_i}{1-\pi_i}=x_i^\top\beta.\]

The fraction is the odds, while its logarithm is the logit. A probability of 0.75 gives odds \(0.75/0.25=3\): three successes per failure in the model’s long-run proportions. Holding other predictors fixed, increasing predictor \(j\) by one unit adds \(\beta_j\) to log-odds and multiplies odds by \(e^{\beta_j}\). It does not add a fixed amount to probability.

3. Write the likelihood

For one independent Bernoulli observation,

\[P(y_i\mid x_i,\beta)=\pi_i^{y_i}(1-\pi_i)^{1-y_i}.\]

If \(y_i=1\), its likelihood contribution is \(\pi_i\); if \(y_i=0\), it is \(1-\pi_i\). Multiply contributions across students and take logs:

\[\ell(\beta)=\sum_i\left[y_i\log\pi_i+(1-y_i)\log(1-\pi_i)\right] =\sum_i\left[y_i\eta_i-\log(1+e^{\eta_i})\right].\]

We maximize this likelihood, rather than minimize squared outcome errors. There is no separate Gaussian error variance: the Bernoulli variance is \(\pi_i(1-\pi_i)\). Dispersion is fixed at 1.

Naively evaluating exponentials can overflow. Rust uses a stable sigmoid and \(\operatorname{softplus}(a)=\max(a,0)+\log(1+e^{-|a|})\); a success contributes \(-\operatorname{softplus}(-\eta_i)\) and a failure contributes \(-\operatorname{softplus}(\eta_i)\). These expressions also avoid cancellation.

4. Derivatives give the Newton step

For one row, write \(\ell_i=y_i\eta_i-\log(1+e^{\eta_i})\). The derivative with respect to \(\eta_i\) is \(y_i-\pi_i\), because \(d\log(1+e^{\eta_i})/d\eta_i=\pi_i\). Also \(d\eta_i/d\beta_j=x_{ij}\). The chain rule therefore gives

\[\frac{\partial\ell}{\partial\beta_j}=\sum_i x_{ij}(y_i-\pi_i).\]

Differentiate again using \(d\pi_i/d\eta_i=\pi_i(1-\pi_i)\):

\[\frac{\partial^2\ell}{\partial\beta_j\partial\beta_k} =-\sum_i x_{ij}\pi_i(1-\pi_i)x_{ik}.\]

These sums are exactly the dot products in the matrix score (gradient) and Hessian:

\[g=X^\top(y-\pi),\qquad H=-X^\top W X, \qquad W=\operatorname{diag}\{\pi_i(1-\pi_i)\}.\]

\(g\) is \(3\times1\); \(H\) is \(3\times3\); \(W\) is an \(80\times80\) diagonal matrix. The negative Hessian \(I=X^\top W X\) is the information matrix. It is positive definite for an identifiable finite fit, making the log-likelihood concave. Newton’s method solves

\[I\,\Delta\beta=g,\qquad \beta_{\mathrm{next}}=\beta+\Delta\beta.\]

We show the information matrix to understand the arithmetic, but the production solver avoids forming/inverting it. It scales columns just as OLS does, then solves a weighted least-squares problem using SVD.

5. Weighted SVD, IRLS and step halving

Let \(D\) contain column lengths, \(A=XD^{-1}\) and \(\theta=D\beta\). The Newton increment is the least-squares solution to

\[B\Delta\theta\approx q,\qquad B=W^{1/2}A, \qquad q=W^{-1/2}(y-\pi).\]

Taking its normal equations produces \(A^\top W A\Delta\theta=A^\top(y-\pi)\), the scaled Newton equation. For \(B=USV^\top\) we get \(\Delta\theta=VS^{-1}U^\top q\), then \(\Delta\beta=D^{-1}\Delta\theta\). See the SVD explanation for the geometry of these factors.

This is iteratively reweighted least squares (IRLS): probabilities and weights change after each fit. Equivalently, a working response \(z_i=\eta_i+(y_i-\pi_i)/w_i\), where \(w_i=\pi_i(1-\pi_i)\), is fitted using weighted least squares. We solve for the increment directly to avoid unnecessarily large working-response values.

Near the optimum, full Newton steps usually work. If a step lowers the likelihood, Rust halves it, with at most 30 halvings. This is a logistic-specific line search, not a general optimizer. Success requires a small full step in every scaled coefficient coordinate and a small likelihood change; a tiny accepted fraction alone is not convergence. The public limit is 100 iterations.

6. Probabilities, residuals and uncertainty

The fitted outputs are \(\hat\pi=\operatorname{sigmoid}(X\hat\beta)\), not labels obtained by a 0.5 threshold. Response residuals are \(y-\hat\pi\). For conventional maximum-likelihood inference,

\[\widehat{\operatorname{Var}}(\hat\beta)=(X^\top\hat W X)^{-1}, \qquad \operatorname{SE}_j=\sqrt{\widehat{\operatorname{Var}}(\hat\beta)_{jj}}.\]

Information is recalculated at the final estimate. There is no multiplication by \(\mathrm{RSS}/(n-p)\). Large-sample Wald inference uses

\[z_j=\hat\beta_j/\operatorname{SE}_j,\qquad p_j=2P(Z\ge|z_j|),\qquad \operatorname{CI}_{95\%,j}=\hat\beta_j\pm1.959964\,\operatorname{SE}_j.\]

Here \(Z\) is standard normal: these are asymptotic z-tests, not the exact Gaussian t-tests used for OLS. Sparse outcomes or near-separation can make Wald inference unreliable even if a finite fit exists. Coefficient intervals are on the log-odds scale; exponentiating their endpoints gives Wald intervals for odds ratios.

7. Likelihood, deviance and AIC

For individual binary observations, the saturated model fits every outcome with probability 0 or 1 and has limiting log-likelihood zero. Thus

\[D=-2\ell(\hat\beta),\qquad \mathrm{AIC}=2p-2\ell(\hat\beta).\]

With an explicit ones column, the null model estimates a constant probability \(\bar y\). Without that column, our null convention has no coefficients and fixed probability 0.5. null_deviance is minus twice that null log-likelihood. df_residual is \(n-p\), but it is not used to estimate a Bernoulli dispersion or select a t distribution. The result intentionally has no OLS R-squared or sigma.

8. Separation, assumptions and things to try

If a predictor combination puts every success on one side and every failure on the other, coefficients can grow without bound while likelihood improves. This is complete separation: there is no finite unpenalized MLE. Quasi-complete separation allows some observations on the boundary. The implementation checks whether an encountered coefficient vector certifies separation; it also rejects rank-deficient information and iteration exhaustion. It is not an exhaustive linear-programming separation detector and does not guarantee detection of every numerically difficult case. It never returns a converged: false partial fit.

The fit requires both classes, finite full-rank inputs, and \(n>p\). This walkthrough uses individual 0/1 outcomes. phit also accepts prior weights, grouped-binomial proportions with trial weights, and offsets (see Matrix model functions). It offers no penalties, Firth correction, or automatic threshold selection. The model assumes independent observations and linear log-odds in the supplied predictors. Missing-data deletion occurs before estimation and warns as in OLS; see the contract.

Try predicting the result before changing the notebook: set all outcomes to 1; replace the outcome by study_hours > 6; duplicate a predictor; convert hours to minutes; or remove the ones column. Which change causes an error, changes the meaning of a coefficient, or changes the null model? Comparing these cases is a way to connect estimation, identifiability and units.

Rust connections

fit_logistic takes ownership of Vec<Vec<f64>> and Vec<f64>, then converts them into nalgebra’s dynamic DMatrix and DVector. The matrix constructor explicitly reads the supplied row order; nalgebra stores its matrix internally by columns. Expressions such as &scaled * &candidate borrow those matrices for an operation so subsequent iterations can reuse them. Iterators build weights, score residuals and output vectors without PHP types entering the core.

LogisticResult is a struct holding the complete fit. Result<LogisticResult, StatsError> makes unsuccessful estimation explicit; the ? operator propagates failed decomposition or line-search operations. There is no mutable model object or general optimizer interface. The dedicated loop updates trial coefficients, checks progress, then recomputes information at the accepted final coefficients.

The binding validates PHP integer/float values, removes missing rows according to policy, calls this owned Rust function, and inserts its vectors and scalars into a PHP associative array. Core errors become PHP exceptions, and deletion produces a warning with row metadata. See the OLS Rust learning notes for more explanation of the shared language constructs.
