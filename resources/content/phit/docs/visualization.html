Documentation figures are drawn with R and ggplot2, from one shared theme in figures/style.R and the figure jobs in figures/render.R. The walkthroughs compute with Python and pass the points to R for drawing. The extension itself has no graphics or R dependency.

Visual conventions

  • Language comparisons keep R, Python, PHP in that order. Python is labeled statsmodels or SciPy reference to identify the actual implementation.
  • R uses blue circles (#0072B2); Python uses orange triangles (#D55E00); PHP uses green squares (#009E73). Color and shape reinforce the labels.
  • Conceptual figures use blue for the reference/population curve, green for the conditional/native curve, orange for an approximation or boundary, and gray for observations. Their legends describe the statistical quantity rather than imply that a curve is an implementation comparison.
  • Use a white background, common sans-serif type, restrained grids and explicit quantity/unit labels. Titles state what is shown; captions state the data or approximation, transformations and relevant limits.
  • Bar charts start at zero. Benchmark facets use their own labeled linear scales and show median bars plus actual timing repetitions. Missing memory is labeled unrecorded, not plotted as measured zero. A measured time of zero is marked 0* because timer resolution can hide a short fit.
  • Log scales are explicit and reserved for quantities spanning orders of magnitude, such as integration errors. The 1e-13 display floor in the quadrature-error plot is disclosed; it never changes stored numerical measurements.
  • Error-versus-reference figures use a zero reference line and label any unit multiplier. Agreement plots are not residual or model-adequacy diagnostics.

Each figure is saved as an SVG with selectable text and a 160-dpi PNG, at fixed dimensions recorded in the figure manifest. The font family is generic sans-serif, so the resolved font can differ across platforms. The conventions use ggplot2’s themes and export controls.

Generate figures without running fits or benchmarks

Install the documentation-only R packages:

install.packages(c("ggplot2", "jsonlite", "svglite"),                 repos = "https://cloud.r-project.org")

From the repository root:

Rscript docs/figures/render.R --all# Or render an individual family/figure:Rscript docs/figures/render.R olsRscript docs/figures/render.R approximationRscript docs/figures/render.R sleepstudy./scripts/render-docs
  • The renderer reads saved benchmark and reference reports and the points in figures/data/. It does not call estimators, regenerate fixtures, or run timings. Refresh the plots when a numerical report changes; a style change does not need new timings.
  • Profile and posterior plots use points exported by the executable walkthroughs. Re-executing those pages updates their JSON point snapshots and figures.
  • SVGs are embedded with namespaced clip IDs, so figures on one page do not interfere.
  • An ordinary site render reuses frozen outputs and saved images. Re-executing the computational notebooks needs the documentation environment.

The manifest records each input’s path and MD5, the image hashes and dimensions, the renderer and theme hashes, the R version, the platform, and the direct package versions. The R package record adds the transitive dependency versions. Other versions may not reproduce the figures byte for byte. The data’s provenance stays in the verification records.
