Install phit with PIE:

pie install phpstats/phit

phit is a PHP extension, so it is installed once per PHP installation rather than per Composer project. Projects that cannot install extensions can use the polyfill, which provides every function except the CSV reader.

Requirements

Requirement Supported
PHP 8.3, 8.4, and 8.5, non-thread-safe (NTS) builds. Thread-safe (ZTS) builds are not supported.
Operating system Linux and macOS. Windows is not supported.
Installer PIE, with unzip or PHP’s zip extension to unpack prebuilt binaries

How PIE installs phit

PIE finds the latest release on Packagist, installs phit.so into the extension directory, and enables it for the PHP it runs under. To target another PHP installation, pass --with-php-config=/path/to/php-config.

  • Linux x86_64 and arm64 with glibc 2.35 or later: PIE downloads a prebuilt binary. No compiler or Rust toolchain is needed.
  • macOS, Alpine and other musl systems, and glibc older than 2.35: PIE builds from source. See Building from source.

Building from source

The build needs these tools, which are not needed at runtime:

  • phpize and php-config from the same PHP installation
  • a C toolchain with autoconf and make
  • stable Rust from rustup
  • Clang and libclang

On Debian or Ubuntu:

sudo apt-get install build-essential autoconf pkg-config \  clang libclang-dev php-devcurl -fsSL https://sh.rustup.rs | sh -s -- -y

In the official php:*-cli images, PHP’s development files are present. Add Clang, libclang, and the image’s $PHPIZE_DEPS.

On macOS, install the Xcode command-line tools (xcode-select --install), Rust from rustup, and PHP and autoconf from Homebrew (brew install php autoconf). If the build cannot find libclang, the development guide shows the variables that select Homebrew’s LLVM.

Prebuilt Linux binaries

Each GitHub release has the binaries PIE uses. They are built on Debian Bookworm for NTS, non-debug PHP, and can be installed by hand. The names follow this pattern, shown for v0.4.4:

PHP x86_64 arm64
8.3 php_phit-v0.4.4_php8.3-x86_64-linux-glibc-nts.zip php_phit-v0.4.4_php8.3-arm64-linux-glibc-nts.zip
8.4 php_phit-v0.4.4_php8.4-x86_64-linux-glibc-nts.zip php_phit-v0.4.4_php8.4-arm64-linux-glibc-nts.zip
8.5 php_phit-v0.4.4_php8.5-x86_64-linux-glibc-nts.zip php_phit-v0.4.4_php8.5-arm64-linux-glibc-nts.zip

Each archive holds phit.so, INSTALL.txt, a manifest.json with the build environment and minimum glibc, the license, and the third-party notices. A .sha256 file sits beside each archive.

f=php_phit-v0.4.4_php8.4-x86_64-linux-glibc-ntssha256sum -c "$f.sha256"unzip "$f.zip" -d phitsudo cp phit/phit.so "$(php-config --extension-dir)/"

Then add extension=phit.so to the PHP configuration of each runtime that needs it, and restart PHP-FPM.

Verify

php -r 'echo phpversion("phit"), PHP_EOL;'

The command prints the installed version, such as 0.4.4.

The command line and PHP-FPM often read different configuration files. Check the web runtime separately, for example with extension_loaded('phit') in a request. Restart PHP-FPM workers after installing or upgrading. Deploying to servers covers containers and FPM.

Declare the dependency

Declare the extension in composer.json so that Composer reports a missing extension at install time:

{    "require": {        "ext-phit": "*"    }}

The polyfill also satisfies ext-phit. See Extension or polyfill.

Upgrade

Run pie install phpstats/phit again, or replace phit.so with the newer binary, then restart PHP-FPM. The release notes and the changelog describe each release.
