Build phit from a checkout, run its tests, and change the implementation. To use phit in an application, see Installation. Run the commands from the repository root.

Environment

The setup follows the official ext-php-rs installation guide and Hello World build workflow:

# macOS: Xcode command-line tools, Rust, PHP (includes headers), libclangxcode-select --installbrew install rust php llvmexport PHP="$(brew --prefix php)/bin/php"export PHP_CONFIG="$(brew --prefix php)/bin/php-config"export PATH="$(brew --prefix php)/bin:$PATH"# If bindgen cannot find libclang:export LIBCLANG_PATH="$(brew --prefix llvm)/lib"

Linux (Debian or Ubuntu with PHP 8.3, 8.4 or 8.5 in the configured repositories):

sudo apt-get updatesudo apt-get install build-essential clang libclang-dev php-cli php-dev curl# Install stable Rust using https://rustup.rs, then source ~/.cargo/env.export PHP="$(command -v php)"export PHP_CONFIG="$(command -v php-config)"
  • Check php -v, php-config --version, and rustc --version.
  • php and php-config must come from the same installation, with the same architecture, thread safety, and debug mode.
  • scripts/check and scripts/check-fpm take PHP from php-config --php-binary unless PHP is set, so another php earlier on PATH, such as Herd’s, does not affect them. Commands you run by hand still need the matching php.
  • On macOS, the linker configuration lets PHP resolve symbols when it loads the extension. Linux needs no extra linker flags.

With Homebrew LLVM’s libclang on macOS, also select the matching compiler and header directory. Xcode’s older arm_neon.h with a newer libclang fails to build:

export LIBCLANG_PATH="$(brew --prefix llvm)/lib"export CC="$(brew --prefix llvm)/bin/clang"export CXX="$(brew --prefix llvm)/bin/clang++"export BINDGEN_EXTRA_CLANG_ARGS="-resource-dir=$($CC -print-resource-dir) -isysroot=$(xcrun --show-sdk-path)"

Build and run

cargo test --workspace --lockedcargo build -p phit --locked# macOS; on Linux the file is libphit.so.export STATS_EXTENSION="$PWD/target/debug/libphit.dylib"php -n -d "extension=$STATS_EXTENSION" -r 'echo phpversion("phit"), PHP_EOL;'php -n -d "extension=$STATS_EXTENSION" tests/ols.phpphp -n -d "extension=$STATS_EXTENSION" examples/ols.php
  • Each suite in tests/ and each script in examples/ runs the same way. ./scripts/check runs all of them.
  • -n skips the ini files, so the tests run against this build only.
  • To load the build permanently, run cargo build -p phit --release --locked and add extension=/absolute/path/to/target/release/libphit.dylib (Linux: .so) to the php.ini that php --ini shows. The optional cargo-php workflow (cargo install cargo-php --locked, then cargo php install --release from crates/php-extension) edits php.ini for you, so back it up first.
  • Rebuild for each PHP version.

Installation covers PIE and the prebuilt binaries. Deploying to servers covers containers and PHP-FPM, and Releasing covers release artifacts.

Numerical dependency policy

  • Linear algebra uses nalgebra’s Rust-native SVD, QR, Cholesky, triangular solves, and pivoted LU. There is one numerical path, with no BLAS or LAPACK dependency and no backend selection.
  • The general mixed fitter uses the pinned Rust-native bobyqa and argmin (Nelder–Mead) crates, which add no C, Fortran, BLAS, or LAPACK requirement.
  • An external numerical backend needs a concrete requirement that justifies the extra build and deployment work.

Changing the implementation

  • Keep statistical calculations in crates/stats-core and PHP conversion in crates/php-extension.
  • Use established numerical crates, and check their APIs against the versions in Cargo.lock.
  • Explain important mathematical steps next to the code.
  • Update the contracts and reference tests when behavior changes.
  • Do not add abstractions for hypothetical models.

./scripts/check runs the offline checks: Rust tests and clippy, every PHP suite and example, the stub and signature checks, the reference manifest, and the site export. Run it before pushing. Verification lists the further checks for each kind of change, and R compatibility covers regenerating R references.

CI runs the checks on macOS and Ubuntu, with fail-fast disabled so one platform’s failure does not cancel the other’s. The packaging workflow tests Linux x86_64 and aarch64 at PHP 8.3, 8.4, and 8.5.
