phit’s fit_mixed_logistic_matrix(), R lme4 glmer(), and an independent Python/SciPy implementation fit the same Laplace marginal ML model. The Python worker is phit’s likelihood and optimizer reference. It is not statsmodels’ Bayesian mixed-model estimator or an optimized Python GLMM package.

Methods

Timing boundaries and correctness

PHP times the complete native call, including conversion and all returned inference/observation arrays. R/Python materialize covariance, standard errors, conditional modes and full fixed/conditional fitted values and residuals. Process time includes startup, CSV load, warm-up and all timed fits.

A report is written only after coefficients, covariance/standard errors, group SD/modes, normalized likelihood and common observation samples agree. Likelihood tolerance is absolute 1e-6 plus relative 1e-8; inference uses absolute 2e-5 plus relative 2e-3; estimates use absolute 2e-5 plus relative 2e-4. Group modes use absolute 5e-5 because large-sample flat-profile optimization produced shifts around 2e-5 in modes near zero; relative error there is not informative.

The installed lme4 version disables derivative checks automatically at large n. The benchmark explicitly enables the final joint Hessian. Its initial BOBYQA run also stopped short on the 10,000-row case; an R-only restart from that fit, with rhobeg=0.001 and nAGQ0initStep=FALSE, resolved it. Both R stages are included in its fit time. The report records these controls, versions and data/binary hashes. Native estimates never seed the R worker.

These models use the one-node approximation. They do not benchmark 61-node integration, random slopes or multiple grouping terms. A larger dataset does not by itself establish approximation accuracy; see the independent integration checks. The full measurements and errors are in the saved report.
