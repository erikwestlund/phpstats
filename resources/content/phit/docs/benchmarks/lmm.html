The release PHP extension, R lme4 lmer and Python statsmodels MixedLM fit identical synthetic observations, with marginal ML (not REML), one random intercept and plug-in GLS fixed-effect inference. The raw report records versions, machine/thread settings, artifact/data hashes and every measurement.

Native Rust optimization

The first implementation repeatedly whitened and SVD-factorized all n rows at every trial variance ratio. The optimized implementation follows lme4’s penalized least-squares elimination idea: separate within-group deviations from group means and cache an augmented QR square-root summary. Each trial now factors p+1+G rows. Covariance is computed only for the selected solution. The same grid, score root refinements, ML objective, rank threshold, input/output contract and numerical tolerances are retained; this is a computational change. The walkthrough derives the reduction and checks its residual norms numerically.

The baseline report preserves all original timings and artifact hashes. These are separate runs on the same machine and identical seeded CSVs, so timing ratios remain subject to system noise. Both reports time complete PHP calls, including conversion and all observation-length outputs. This is native nalgebra QR/SVD, with no BLAS/LAPACK or sparse backend dependency. lme4 uses a general sparse Cholesky implementation; our specialized square-root reduction reuses its mathematical elimination idea while retaining SVD rank checks.

Timing boundaries and methods

Each worker loads one CSV, warms up once and fits five times. Timed calls include estimation, fixed-effect covariance and normal Wald inference, variance components, ICC, likelihood/AIC, all population/conditional fits and both residual vectors, and all conditional group estimates. PHP also validates/copies inputs and converts all output arrays and group/sample metadata inside the timer. Startup, CSV parsing, data generation and final compact JSON serialization are excluded.

R uses lmer REML=FALSE with bobyqa rhoend=1e-10. Python uses MixedLM ML BFGS with gtol=1e-10 and recalculates plug-in GLS covariance to align with the documented convention. Its native joint observed-Hessian covariance is not compared as though it were identical. Rust scans a log-ratio profile grid and refines analytic-score roots with compact weighted SVD GLS fits, after a one-time QR reduction. These algorithms and stopping rules differ. The comparison measures complete declared API behavior, not a single common solver.

Simulation and numerical checks

NumPy RNG seed 20261011 generates correlated study hours and prior scores, independent standard-normal extra predictors, and schools with roughly equal sizes. Outcomes follow

\[y_i=50+1.8\,\mathrm{hours}_i+0.2\,\mathrm{prior}_i +0.5\sum_j\mathrm{extra}_{ij}+b_{g(i)}+\epsilon_i, \quad b_g\sim N(0,6^2),\quad\epsilon_i\sim N(0,5^2).\]

This sample is separate from the saved small teaching dataset. Identical 17-significant-digit CSVs are used by every worker. All coefficient-level fields, variance components, ICC, likelihood/AIC and all group effects are checked. Observation-length outputs are fully materialized, but cross-runtime checks sample ten evenly spaced rows; small fixtures check every row.

Benchmark absolute tolerance is 1e-7. Relative tolerance is 1e-6 for ordinary outputs, 1e-5 for covariance, SE, z-statistics, variance components, sigma and ICC, and 1e-9 for likelihood/AIC. Small saved references use the tighter uniform 1e-7 + 1e-6 × abs(reference) policy.

The first 100,000-row check found R’s between-group variance differed from the analytic-score solution by about 2.6e-6 relative while log-likelihood differed by only about 8e-10. The log-ratio profile score was approximately 2.55e-4 in R, -1.88e-6 in Python and 3.12e-11 in Rust. A flat likelihood and floating-point objective resolution limit independently optimized variance-component agreement; the variance-sensitive benchmark tolerances reflect that measured distinction. They do not replace the closed-form ML check or justify relaxing likelihood agreement. The finite Rust profile grid itself is not a global-optimum proof.

Numerical failures abort before publication. Ordinary renders read saved results and do not rerun these timings. See the contract for model and inference limits.
