Numerical findings and fixes

The saved native/mpmath errors are typically below 1e-13; the largest is about 8.34e-13 in a large-df chi-square log tail. Native tests keep the original operation-specific 1e-12 tolerances. R and SciPy have documented endpoint and tail differences, with an independent reference used only when the saved references justify it. In particular, SciPy’s large-df chi-square lower-tail error is visible in both the reference record and benchmarks. Unavailable high-precision values are recorded as null, and reduced subnormal precision is disclosed.

Additional verification fixed two arithmetic bugs: overflowing descriptive variance no longer becomes zero through max(NAN, 0), and finite large NB size/mean values whose sum overflows no longer become a false point mass. Negative descriptive weights are rejected before missing-value deletion. R reference values at ordinary scales remain within the established tolerances; existing regression APIs and numerical paths are preserved.

Reuse and RNG decisions

The executable reuse experiment found that the new Student-t quantile improves R agreement for the six tested OLS critical values, but changes their rounding. The public normal log-CDF differs at 17 saved points from the established probit calculation. Regression behavior had to be preserved, so neither path was replaced. A future refactor can use this evidence to make an explicit model compatibility decision.

Random sampling is implemented with dist_{family}_rng(n, seed, ...parameters). Each call owns a pinned ChaCha20 stream and transforms open-interval uniforms through the existing inverse CDF. The sampling contract defines seed ownership, count/type/range policies and reproducibility limits. Independent Python ChaCha/PCG/Open01 equations and base-R quantiles verify the stream and samples; benchmarks verify sampled points and full-vector moments before recording seeded-call timings. The earlier handoff recommendation to defer RNG has been superseded by this implementation.

Release and platform limits

The new completion run verifies macOS arm64/PHP 8.5.10. Earlier packaging evidence in deployment covers Linux arm64 PHP 8.3/8.4/8.5 for the preceding source snapshot. That historical evidence does not establish that the latest hardening changes passed those environments. The configured remote amd64/PHP matrix and updated binary/container builds must run as part of the separate release process. Windows/ZTS remain outside the supported package matrix. Benchmarks do not establish performance bounds on other machines or all finite/extreme arguments.

Version and tag selection, Packagist registration, and binary publication were left to the release process.
