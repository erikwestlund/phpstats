phit fits each model to complete rows. A row with a missing value in any variable the model uses is left out, the fit warns once, and the result records which input rows it used.

Example

Two of these six flats have a missing value: row 2 has no rent, and row 3 has no area. The note column is not in the formula, so its missing values do not matter.

use function Phit\fit_ols;$flats = [    'rent' => [        1879.25, 1805.03, null, 1267.85, 1509.24, 2240.1,    ],    'area' => [74.4, 57.4, 66.4, NAN, 45.7, 92.4],    'note' => [null, 'corner', null, null, 'garden', null],];$fit = fit_ols('rent ~ area', $flats);printf(    "%d of %d rows used, %d dropped\n",    $fit['n_observations'],    $fit['n_input'],    $fit['n_dropped'],);printf(    "retained: %s\ndropped:  %s\n%d residuals\n",    implode(', ', $fit['retained_rows']),    implode(', ', $fit['dropped_rows']),    count($fit['residuals']),);
4 of 6 rows used, 2 dropped
retained: 0, 1, 4, 5
dropped:  2, 3
4 residuals

The call also raises one PHP warning with this message:

Phit\fit_ols(): Phit\fit_ols dropped 2 of 6 observations with missing values (listwise deletion)

Behavior

  • missing: 'drop', the default, removes incomplete rows. missing: 'raise' throws instead, without fitting.
  • Only PHP null and NAN are missing. Infinities are errors, and strings such as '' or 'NA' are not treated as missing.
  • Formula fits check only the columns the formula uses, including weights, offsets, and grouping factors.
  • fitted and residuals hold one value per retained row, in retained_rows order. They are not padded with null.
  • Row positions count inputs in iteration order, from zero. They are not PHP array keys.
  • Every statistic, including df_residual, uses the retained rows.
  • phit does not impute values.

Interpreting a complete-case fit

Dropping incomplete rows changes the sample the model describes. Estimates can be biased when missingness is related to the outcome or the predictors. Report how many rows were dropped and why values are missing. phit offers no imputation or missing-data model.

R’s explicit na.action = na.omit and statsmodels’ explicit missing='drop' fit the same complete-case sample. They do not all warn by default. The warning and the row accounting are phit’s own contract. The three-implementation verification checks that phit, R, and statsmodels retain the same rows and give the same results.

Validation

Validation inspects every original value and shape before any row is dropped, so a missing value cannot hide an invalid value or a ragged row. After deletion, the retained fixed design must still have more rows than columns (counting the intercept) and full numerical rank. If no usable fit remains, the call throws.

For the matrix functions, the variables checked are the supplied predictors, outcome, weights, offsets, and groups. Strings, booleans, objects, and absent or ragged matrix elements are errors there. Numeric zero is a valid value.

// missing: 'drop'$result = Phit\fit_ols_matrix(x: $x, y: $y);// Reject missing values.$result = Phit\fit_ols_matrix(    x: $x,    y: $y,    missing: 'raise',);

Warning and accounting

A successful fit that drops rows emits one E_WARNING with the number dropped and the original sample size. In the polyfill it is an E_USER_WARNING. Complete data emits no warning. A failed fit throws and returns no accounting. The warning text is descriptive and is not a stable machine-readable interface.

Every successful result includes:

Key Meaning
n_input int: original observations
n_observations int: retained observations used in estimation
n_dropped int: omitted observations
retained_rows list: original zero-based positions retained, ascending
dropped_rows list: original zero-based positions omitted, ascending

To place residuals back at their original positions:

foreach ($result['retained_rows'] as $out => $in) {    $residualAt[$in] = $result['residuals'][$out];}

Log or display the warning with your normal warning handling, and use the counts for reporting. PHP settings can hide warnings, so applications should also check n_dropped. An error handler that turns warnings into exceptions aborts the call. Use missing: 'raise' to prohibit omission explicitly. Do not suppress the warning without recording the deletion.

Model-specific rules

Logistic. fit_logistic_matrix() follows the same deletion, warning, and row-accounting policy as fit_ols_matrix(). With default unit trial weights, numeric outcomes must be exactly 0 or 1, including rows with missing predictors. After deletion both classes must remain and n must exceed p. Residuals are response residuals, y minus the probability. Residuals and fitted probabilities follow retained_rows order.

Probit and Poisson. Probit follows the binary rules above. Poisson validates nonnegative integer counts before deletion, and at least one positive count must remain after it. Zero counts are observed values, not missing ones. Every estimator warns once on a successful fit that dropped rows, exposes original row positions, and supports missing: 'raise'.

Mixed-model group IDs. fit_mixed_gaussian_intercept_matrix() drops a row if x, y, or the group ID is missing. A missing group ID is null. NAN and float group IDs are invalid labels and are rejected. Group labels and sizes describe the retained sample, and a group removed entirely is absent from the results. If deletion leaves one group, only singleton groups, or too few observations for the fixed design, fitting fails. Use retained_rows to align conditional and population fitted values and both residual definitions with the original data.

Weights, offsets, and random terms. Optional weights and offsets, and every random term’s z and groups, share one listwise deletion mask. Their original lengths, types, and values are validated before deletion. Grouped-binomial proportions with positive integer trial weights are allowed. Invalid success or trial counts are errors, even in rows that would otherwise be dropped. General mixed fits warn once and return original row positions like the other functions. tests/r-compatibility.php and tests/lmm-expanded.php cover these cases.

Mixed logistic. fit_mixed_logistic_matrix() applies the same policy across x, proportions, groups, trial counts, and offsets. Trial counts above 1,000,000 are rejected before rows are dropped. Near-integer success encodings within tolerance are canonicalized only after validation and deletion. A sample with no successes or no failures then fails, since an unpenalized fit would not be finite.

Implementation and history

The PHP binding applies the omission policy before calling the Rust core. The Rust fit_ols() contract still requires complete, finite numeric vectors.

The first API rejected null and NAN. Callers that need that behavior should pass missing: 'raise'. Code that drops rows itself before calling phit must report that deletion itself, because phit can account only for the rows it receives.
