The formula functions take an R model formula and a data set of named columns. They build R’s model matrix and fit it with the same estimators as the matrix functions. Each result has its matrix function’s complete contract plus coefficient names.

Phit\model_matrix(    string $formula,    array|object $data,    string $missing = 'drop',): array;Phit\fit_ols(    string $formula,    array|object $data,    string $missing = 'drop',    array|string|null $weights = null,): array;Phit\fit_generalized_linear(    string $formula,    array|object $data,    string $family = 'gaussian',    string $link = '',    string $missing = 'drop',    array|string|null $weights = null,): array;Phit\fit_mixed_gaussian(    string $formula,    array|object $data,    bool $reml = true,    string $missing = 'drop',    array|string|null $weights = null,    ?array $start = null,    int $maxEvaluations = 20000,    float $tolerance = 1e-7,    string $optimizer = 'bobyqa',    float $objectiveTolerance = 1e-12,): array;Phit\fit_mixed_logistic(    string $formula,    array|object $data,    string $missing = 'drop',    array|string|null $weights = null,    int $quadraturePoints = 1,    int $maxEvaluations = 20000,    float $tolerance = 1e-7,): array;

PHP reflection reports $data and $weights as mixed. The stubs in stubs/phit.php document the accepted types.

Example

use function Phit\fit_ols;$data = [    'rent' => [        1879.25, 1805.03, 2022.29, 1267.85,        1509.24, 2240.10, 959.51, 2386.54,    ],    'area' => [        74.4, 57.4, 66.4, 49.1,        45.7, 92.4, 37.0, 93.9,    ],    'district' => [        'north', 'south', 'north', 'east',        'south', 'north', 'east', 'south',    ],];$fit = fit_ols('log(rent) ~ log(area) + district', $data);echo implode(', ', $fit['columns']), "\n";
(Intercept), log(area), districtnorth, districtsouth

columns names the coefficients in order. named maps each name to its coefficient, and every list key, such as p_values, follows columns.

Data

$data is an associative array of columns, name => list of values. An object is also accepted: phit calls its public toModelData() method, or toColumns() when that is absent, and uses the returned array. Exceptions from those methods propagate unchanged. phibble’s DataFrame::toModelData() returns this shape.

Each column is one of the following.

  • Numbers: integers and floats. null and NAN are missing. Infinity raises 1003.

  • Booleans: a logical column. R codes it as a two-level factor named {col}TRUE.

  • Strings: a character column. It becomes a factor whose levels are the distinct retained values in byte (C-locale) order, which is R’s order under LC_COLLATE=C. Other R locales can sort mixed-case or accented strings differently.

  • A factor descriptor: an array with exactly the keys levels (list of unique strings), codes (list of 0-based integers, null for missing), and ordered (bool). Levels keep the caller’s order and the first level is the reference.

  • Dates arrive as numbers, for example days or seconds since the epoch.

  • Every column must have the same length (code 1002).

  • Only the columns a formula uses are type-checked.

  • An unknown column, a malformed factor descriptor, a referenced list-column or mixed-type column, or a list of row arrays raises 1001.

Formula syntax

The formula grammar and operator precedence follow R.

Syntax Meaning
y ~ a + b Main effects. ~ a + b (no response) is valid for model_matrix.
- 1, + 0, 0 + Remove the intercept. + 1 restores it.
a:b Interaction columns for every combination of the coded variables.
a * b a + b + a:b.
(a + b + c)^2 All main effects and interactions up to order 2.
a / b a + a:b (nesting). b %in% a is b:a.
- term Remove a term, for example a * b - a:b.
. Every data column that does not appear in the response.
offset(expr) A fixed known offset. Several offsets are summed.
(x | g), (x || g) Random-effect terms (see below).

Terms are ordered as R orders them: main effects first, then two-way interactions, and so on, with ties in formula order. Within an interaction, variables appear in order of first appearance in the formula, and the first variable varies fastest in the column order. y ~ b:a + a therefore gives bv:ap, bv:aq, and so on.

Inline transforms

The following functions can appear as variables or inside one another. Column names are R’s deparsed expressions, including R’s spacing and its 15-digit number formatting, for example I(x^2), I(area/beds), I(x * 1e+05), and log(x, base = 2).

  • log(x), log(x, base), log2, log10, log1p, exp, expm1, sqrt, abs, sin, cos, and tan.
  • I(expr) with + - * / ^, numbers, parentheses, unary minus, comparisons (< > <= >= == !=), &, |, and !. A comparison gives a logical column, such as I(x > 3)TRUE. Strings compare with character and factor columns: I(region == "north").
  • poly(x, degree) gives R’s orthogonal polynomials and poly(x, degree, raw = TRUE) gives raw powers. Columns are named poly(x, 2)1, poly(x, 2)2, and so on. Orthogonal polynomials are computed over all input rows before deletion, as in R, and reject missing values. Raw polynomials allow them.
  • factor(x), as.factor(x), and ordered(x) convert a column. Numeric levels are sorted numerically and labelled with R’s number formatting. Levels come from all input rows, as in R’s model frame.
  • as.numeric(f) gives 1-based factor codes.
  • cbind(successes, failures) is a binomial response for fit_generalized_linear and fit_mixed_logistic.

Any other function raises 1007. A transform result of NaN, such as log(-1), is missing and is deleted like any other missing value (R also removes it, with a “NaNs produced” warning). An infinite result, such as log(0), raises 1003.

Contrasts

Unordered factors, strings, and logicals use treatment contrasts. The columns are named {variable}{level} for every level after the first. Ordered factors use contr.poly, with columns .L, .Q, .C, ^4, and so on. R’s coding rule decides whether a factor in a term receives contrasts or one indicator per level. A factor is coded by contrasts when the term without it appears earlier in the formula, or is empty. Without an intercept, the first factor in the first term that contains one receives full indicator coding. These rules give R’s columns for formulas such as y ~ 0 + f, y ~ x:f, y ~ f:g, and y ~ f * g - 1.

Missing values and unused levels

  • Listwise deletion uses only the variables the formula references: the response, transforms, offsets, weights, grouping factors, and random-effect columns. Other columns may contain missing values.
  • missing: 'drop' removes incomplete rows with one E_WARNING. missing: 'raise' raises 1001. Missing values describes the warning and the row accounting.
  • model_matrix keeps unused factor levels, as R’s model.matrix() does. Their indicator columns are all zero.
  • The fitting functions drop levels that are absent after deletion, as lm(), glm(), lmer(), and glmer() do through drop.unused.levels = TRUE.
  • Character levels always come from the retained rows.

model_matrix

The result has these keys.

Key Contents
y Response values. A factor response gives 0-based codes plus response_levels. cbind(s, f) gives [s, f] rows. null without a response.
x Design rows for retained observations, including (Intercept) when present.
columns, assign R column names and R’s assign attribute (0 for the intercept).
terms, intercept R term labels and whether the intercept is present.
formula, response The deparsed formula and response expression.

x includes the intercept column, so pass it to a matrix function with intercept: false. Each random entry has the shape that fit_mixed_gaussian_matrix expects:

$mm = Phit\model_matrix('y ~ x + (1 + x | g)', $data);$fit = Phit\fit_mixed_gaussian_matrix(    x: $mm['x'],    y: $mm['y'],    random: $mm['random'],    intercept: false,);

fit_ols and fit_generalized_linear

fit_ols returns the full fit_ols_matrix result. fit_generalized_linear supports four family and link combinations. An empty link selects the canonical link.

Family Links Core
gaussian identity fit_ols_matrix, plus deviance, null_deviance, and aic as R’s glm() reports them
binomial logit, probit fit_logistic_matrix, fit_probit_matrix
poisson log fit_poisson_matrix
  • Other families or links raise 1007.
  • A binomial response can be 0/1 numbers, booleans, a factor or character column (the first level is failure and every other level is success, as in R), proportions with integer trial weights, or cbind(successes, failures).
  • $weights is an array aligned with the original rows, or the name of a numeric column. Weights must be positive, and a missing weight deletes its row.
  • Random-effect terms raise 1007 and name fit_mixed_gaussian and fit_mixed_gaussian_matrix as the alternatives.

Every formula fit adds these keys to the matrix result:

Key Contents
formula, response The deparsed formula and response expression
columns Coefficient names, aligned with coefficients
named column => coefficient
terms, assign, intercept R term labels, R’s assign attribute, and whether an intercept is present
predvars State that prediction reuses: each factor’s levels after deletion and each orthogonal poly() basis (R’s xlevels and predvars)
family, link fit_generalized_linear and fit_mixed_logistic only

fit_mixed_gaussian and fit_mixed_logistic

fit_mixed_gaussian fits lme4-style bar terms with the fit_mixed_gaussian_matrix estimator. REML is the default, as in lme4::lmer().

Bar term Meaning
(1 | g) Random intercept
(x | g), (0 + x | g) Correlated random intercept and slope; slope only
(x || g) Uncorrelated intercept and slope (diagonal covariance)
(1 | g1) + (1 | g2) Several independent terms
(1 | g1:g2) Interaction groups
(1 | g1/g2) Nesting: (1 | g1) + (1 | g2:g1), with lme4’s group name and g2level:g1level labels
  • The result is the fit_mixed_gaussian_matrix contract. Each random entry also has label, group, columns, and correlated.
  • effects_cond_var lists one k×k conditional covariance per group, in group_labels order. These are the blocks that ranef(fit, condVar = TRUE) attaches as postVar. For (x || g), lme4 reports only the diagonal of each block.

fit_mixed_logistic supports exactly one random intercept (1 | g) with the binomial family and logit link, using the fit_mixed_logistic_matrix estimator.

  • quadraturePoints is lme4’s nAGQ.
  • Responses follow fit_generalized_linear.
  • random_effects_cond_var is the conditional variance of each group’s mode, as lme4’s postVar.

Prediction: predict

predict($fit, $newdata) predicts from any formula fit, as R’s predict() does for lm, glm and merMod objects. It rebuilds the fit’s formula over $newdata, which needs the predictor columns but not the response.

$fit = Phit\fit_generalized_linear(    'am ~ wt + poly(hp, 2)',    $cars,    family: 'binomial',);$p = Phit\predict(    $fit,    ['wt' => [2.2, 3.4], 'hp' => [95, 180]],    type: 'response',    seFit: true,);// $p['fit']: probabilities. $p['se_fit']: delta-method SEs.
  • Factors are coded with the levels the fit saw. A level the fit never saw raises 1001 with R’s message (factor g has new level z). Logical and character columns work the same way.
  • poly(x, k) evaluates the fitted orthogonal basis at the new values, as R’s predict.poly() does. It is not refitted to the new data.
  • offset() terms are evaluated over $newdata and added.
  • A row with a missing predictor predicts null and is listed in missing_rows. Every list has one entry per $newdata row.
  • type: 'link' (the default) returns the linear predictor. type: 'response' applies the inverse link, and seFit then uses the delta method, as R does.
  • interval: 'confidence' or 'prediction' adds lower and upper for fit_ols fits, using t with df_residual at level. A prediction interval adds the residual variance; as in R, it assumes constant variance for a weighted fit.
  • For fit_mixed_gaussian and fit_mixed_logistic fits, predictions add each known group’s random effects (lme4’s default re.form = NULL). random: false gives population predictions (re.form = NA), and the grouping columns can then be absent. An unseen group raises 1001 unless allowNewLevels: true, which predicts it at the population level. Mixed predictions have no standard errors, as in lme4.

GLM standard errors use the covariance at the final coefficients. R’s predict.glm() uses vcov(), which reuses the weights of the iteration before the final one, so the two differ by about the size of R’s last IRLS step. See GLM covariance.

Differences from R

  • Character levels use byte order. R’s default locale collation can order mixed-case or non-ASCII strings differently.
  • Rank-deficient designs raise 1004. R reports NA (aliased) coefficients instead.
  • Weights must be positive. R accepts zero weights. cbind() rows with zero trials are rejected; R gives them zero weight.
  • A response that also appears on the right-hand side raises 1001. R drops the term with a warning.
  • Only the functions listed above can be evaluated. factor() takes one argument, and poly() takes one variable.
  • x %in% a is labelled x:a. R labels the term x %in% a; the columns are identical.
  • model_matrix returns factor responses as 0-based codes with response_levels.
  • fit_generalized_linear(family: 'gaussian') uses t-based intervals, as fit_ols_matrix does. R’s confint.default() is z-based and confint() profiles the likelihood.
  • fit_mixed_gaussian orders groups and effects by first appearance after deletion and keeps random terms in formula order. lme4 sorts levels and orders terms by their number of levels. Estimates are invariant to these orderings.
  • Duplicate column names collapse in the named map; columns keeps every name.
